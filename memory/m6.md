## Traps

* Dropbox mtime churn: `edit` refuses after a read if the file changed seconds
  ago; re-read immediately before editing.  (Hit several times here.)
* `mpp_fixture::make_cfb` pads the FAT to whole 512-byte sectors, so its FAT
  array has `num_fat*128` entries, not the sector count.  A slack test must add
  `(fat_entries - sectors) + n` appended sectors to get exactly `n` slack.
* `mpp_fixture::put_u32` is the only u32 writer; `mpp_error_paths.cpp` now has a
  small local `get_u32` for reading the header's DIFAT/FAT words.
* Do not put a file named `inspect.py` under a Python path used with `olefile`:
  it shadows stdlib `inspect` and `olefile` fails on import.
* `MPP14` FixedMeta offsets are trustworthy: use them to *detect* a different
  row layout, not to slice 206-byte rows as if they were 202 (the fields shift
  differently).
* The reader's CFB warning is also consumed by `core/cal`, `app` and
  `core/session` for free because they share `mpp::CompoundFile`; only
  `Document`-based callers see `Document::warnings`.
* `ctest` includes `engine_diff` suites that use `mppwrite::CfbDocument`; they
  pass on committed fixtures.  Do not "fix" the sf248 dump rejection here.
