## Invariants that must not drift

* **Seven command tabs**, in order: Task, Resource, Report, Project, View, Help,
  Gantt Chart Format.  File is chrome, not one of the seven.
* **The contextual tab is model-present always, visible only in the Gantt
  (`task_sheet`) view.**  `MainWindow::show_view()` drives
  `RibbonBar::set_contextual_visible(mode == app::ViewMode::task_sheet)`; the
  gate proves it through the real `view_resource_sheet` / `view_task_sheet`
  QAactions.
* **The Task tab must keep fitting 1920.**  `qt_empty_state` asserts all eight
  groups and all 30 buttons are visible at 1920 (the empty project opens on the
  Task tab), and `qt_parity_geometry` measures the same ribbon.  Adding a Task
  group/button can break both.  The measured Task tab is 8 groups; the parity
  fixture's geometry otherwise must not move (row 22, header 43, gutter 60,
  splitter 0.45924, day 24, tiers 2, 9 columns, 3 colours).
* **Text-labelled commands only.**  The port has no combos/checkboxes/palettes
  in the ribbon.  Combo/checkbox controls are carried as their label button;
  Gantt Chart Style is caption-only; unlabelled formatting widgets (colour
  pickers, %-complete micro-buttons, indent arrows) are not modelled.
* **Only exact command matches carry a `MenuAction`.**  Everything else is
  `app::MenuAction::none` => disabled with `not implemented in this port`.
  Do not add ribbon-only handlers to `main_window.cpp`; new commands go through
  `app::menu_model` + `command_status.h` + `handle_action()` first.
* `command_status.h` is the single implemented set and is **not** owned by this
  lane; the `// UNIMPLEMENTED` marker is read by the backlog generator.

## Traps

* **Dropbox mtime churn**: the `edit` tool often refused ("file changed since it
  was read") even with no content change.  Re-read the exact block and retry;
  short edits usually land.
* The workspace is shared with other lanes: `main_window.cpp` (E7) and
  `entry_columns/sheet_table_model/sheet_views/plan_document` (S6) changed while
  this lane built.  An app_qt build can pick up their in-flight code; the wave
  gate is the clean tree.
* `empty_state_test.cpp` at 1920 requires **all** Task groups/buttons visible
  and the `>>` hidden; at 900 it requires the `>>` visible.  Keep the Task tab
  as measured.
* The `>>`/tab-chevron buttons are layout-external children of `page_`/`tab_row_`
  (`clear_page()` must not delete them).  The per-group button/action vectors are
  cleared in `clear_page()` and pushed in `build_page()` in page order.
* `findChildren` order is creation order; the gate relies on it for
  caption -> group-box mapping (as `empty_state` already does).
* At 1920 our text-button ribbon fits every tab, so a "must overflow at 1920"
  assertion is wrong; assert the chevron **equivalence** per tab, and prove the
  overflow path at 900.
