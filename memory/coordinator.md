## The five findings that matter

1. **A date edit now sticks in Project — and the manual mode bit is measured.**
   `mppwrite::save_date_edits` writes SNET at FixedData `+64/+66` **and clears
   Fixed2Meta entry byte `+8` bit `0x80`**. Project reopens the row at the pinned
   date with `Manual=False`, Duration untouched, Finish recomputed through the
   calendar. SNET alone on a manual row is **stored but ignored** (type 4 and the
   exact date read back, Start unchanged) — that is why W29 never moved Start.
   Fixtures `corpus/probe/w37-snet-auto.mpp` (FNV 0xc917b3380e0d660c, honoured,
   regenerated by the API itself) and `w37-snet-save.mpp` (negative control).
   Consequence: manual scheduling is not preserved; each converted row warns.
   `spec/mpp-writer.md` §10.8 records it.
2. **`app::date32_from_packed` was one day late.** File epoch day 0 = 1983-12-31,
   date32 day 1 = 1984-01-01 with `weekday_of_day(d)=(d-1)%7`, so **file day D ==
   date32 day D**. Fixed to identity; pinned by 15346→2026-01-05,
   15636→2026-10-22 and PROJECT_A's 15633→Monday.
3. **`core/session`** (W36): load → reader → plan recalc (with the decoded
   calendar) → RecordSet → SheetModel + GanttSource + copyable `Status`,
   821 checks with corpus / 121 without, status text provably name-free.
4. **`core/render`** (W39): dependency-free PDF 1.7 writer + sheet/Gantt reports,
   169 checks, externally validated with pypdf, deterministic bytes.
5. **ALAP was a stored-word misread, not an engine bug** (W41): on an ALAP row
   Project's displayed Start/Finish are `+96/+100` (calculated) while
   `+104/+108` holds the early dates — the two pairs are not interchangeable
   there. The old 18/20 divergence was our comparison, not our engine.

## Traps hit this wave (do not relearn)

* **`call` is cmd syntax.** In pwsh chain vcvars and cmake:
  `cmd /c '"C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat" >nul && cmake ... && cmake --build ...'`.
  A bare `call` fails as "not recognized", and then every cmake/ctest is missing.
* **`git push` failed with `SEC_E_NO_CREDENTIALS`** under the file sandbox while
  `gh auth` was fine; the same push succeeded with wider access. Do not run
  `gh auth setup-git` (it needs to write `C:\Users\...\.gitconfig`).
* **`git status --cached` does not exist** (`git diff --cached`); a failed status
  after a successful `git add` looks like a failed commit and is not.
* **Dropbox mtime churn**: `edit` fails with "file changed since it was read"
  seconds after a read. Re-read the exact lines and retry.
* **Root configure races**: one lane's `CMakeLists.txt` naming a file another
  lane has not written yet breaks everyone's configure. Retry the identical
  configure; never edit the other lane.
* `ctest -R cal` matches `core_sched_calendar` and `plan_recalc`; use `^cal$`.
* `plan_recalc_tests` rewrites `tests/data/project_a_recalc_golden.tsv` whenever corpus
  is present — a stream must never re-pin; the coordinator re-pins deliberately.
* `app/` is a standalone CMake project; only `main.mm` needs macOS. Verify the
  headless tests locally (`app_layout`, `app_selection`, `app_document`);
  `app-macos` CI is the only proof for ObjC++.
