## The mechanism (reuse this, don't reinvent it)

`PlanDocument::fill_computed_columns()` runs at the end of `build_gantt()` — after
`view_ = app::sync_plan_from_records(...)` — and writes the three derived texts into
the **RecordSet** under the same field ids the stored columns carry.  The model and
delegate then paint them as ordinary text cells; there is **no view-layer special
case**, and a structural link edit re-derives in the same rebuild.  Any future
"computed column" (Indicators, Total Slack, …) belongs in the same place.

`% Complete`'s percent sign is set on the `SheetColumn.kind` in
`PlanDocument::stored_columns()` (not in a painter), so the clipboard sees it too.

## Measured syntax (Project's Predecessors/Successors text)

From `corpus/reference/2026-10-23-msproject/project-gantt-loaded-clean.png`:

* entries are `,`-separated with **no space** (`40,36`, `18,33FS+20`);
* a **lag-free FS** link is the bare ID (`4`, `33`);
* an **FS link with a lag keeps `FS`** (`9FS+50 days`) — this one cost a wrong
  first implementation; the capture is the authority;
* `SS`/`FF`/`SF` always print (`33SS`);
* list order is the **FILE's link order, not ascending ID** — the capture's task 35
  shows `40,36` and task 36 `39,37`, both exactly the stored order;
* lag text is the sheet's own duration formatter, so `50 days` here vs Project's
  `50 d` (that file uses abbreviated duration labels — a shell-wide, pre-existing
  divergence, also visible in the Duration column).
