# memory/e7.md — the project's new-task scheduling default (wave 22)

Read `docs/handoff/e7.md` for the byte search; this is the durable summary.

## The fact

Project 2021's **File > Options > Schedule > "New tasks: Manually Scheduled /
Auto Scheduled"** is stored per file, in the project props stream:

| item | value |
|---|---|
| stream | `114/Props` (MPP14); `112/Props` in a 2010+ project saved down to MPP12 |
| record id | **`0x024013c8`** |
| framing | 16-byte header, then `u32 len, u32 id, u32 kind, payload`; kind **2**, length **2** |
| value | **0 = Auto Scheduled**, **1 = Manually Scheduled** |
| absent | original Project 2007 MPP12 files (the option did not exist); some writer-patched probes |

`ProjectRow::new_tasks_manual` / `new_tasks_manual_stored` expose it.
`mpp::read_new_task_mode(path)` is the path-only accessor the Qt shell uses
(`PlanDocument` is S6-owned and does not expose the `mpp::Document`).

## Why the id is trustworthy

1. Project's own binary name table (`decompiled/part_0000.c` `FUN_1401b8a70`)
   lists `QNEWTASKSAREMANUAL` at index 64; the props dump helper maps
   `index = (id & 0xffff) - 5000`, and the id of index *i* is
   `0x02401388 + i` → `0x024013c8`.
2. Neighbouring names in the same table verify the index rule against the same
   files: `QISNEWTASKSESTIMATED` `0x0240138a` matches MSPDI
   `<NewTasksEstimated>`; `DAYSPERMONTH` `0x0240138f` = 20;
   `PROJECTCURRENCYCODE` `0x024013bb` = `"AUD"`; `CREATIONSYSTEMTIME` is 16 B.
3. Project's own MSPDI exports carry `<NewTasksAreManual>`; the 5 files with an
   export agree 10/10 with the bytes (the bit and the u16 per file):
   PROJECT_A/B (wct/tender-export) = 0, assign1/lagff1/w9-resourcetypes = 1.
   PROJECT_A also has the clean capture whose status bar says "New Tasks : Auto
   Scheduled".
4. 133 files scanned; every present record is kind 2 / length 2; 102 value 1,
   9 value 0, 16 absent (2007 MPP12), 6 MPP8/9 unreadable.

## Status bar behaviour (wave 22)

`MainWindow::update_status_mode()`: loaded + record 0 → "New Tasks : Auto
Scheduled"; loaded + 1 → "…Manually Scheduled"; new project, missing record or
undecodable value → **Manual fallback** with a tooltip note.  Decision 11 is
unchanged for a new project.  `open_file` reopens only the container/props for
the lookup; `new_project()` resets to the default.

## Traps

* Do not confuse this record with `0x0240138a` (`QISNEWTASKSESTIMATED`) or with
  the task-level manual bit (`Fixed2Meta +8 0x80`).  All three are different.
* `0x02401392` is `DOCHASALIAS`, not a custom-field flag (the W50 "custom-field
  data in use" name was an empirical correlation; the property table gives the
  real name).  Do not rename the existing writer constant on this alone without
  re-measuring the writer path.
* The record exists in MPP12 files **saved down from 2010+**; absence is a
  property of original 2007 files, not of the format number.
* core/mpp decodes the one record itself (five-line framing); it does not link
  core/props, and must not start doing so for this.
* E7 owns only the status wiring in `main_window`; `plan_document.*` is S6's and
  does not carry this field — use `read_new_task_mode()`, do not add a member
  there unilaterally.

## Next / open

1. No writer: the record is decoded, not saved.  A save round-trip of a new
   project still keeps whatever `114/Props` is copied; adding an API needs a
   Project acceptance fixture (set the option, save, diff) — not attempted.
2. A capture of PROJECT_A's own status bar in Project would turn the visual
   evidence from the clean reference into a per-file oracle; the clean capture is
   already the same stored table, so this is low priority.
3. If the wave ever gets a file whose flag was toggled in Project with the other
   fields held constant, add it as the perfect single-variable fixture; today the
   labels come from exports, not a controlled toggle.
