## Durable facts

* **Schema is `engine-diff/2`** (`tests/engine_diff_tests.cpp` `dump_file`,
  `scripts/engine_diff.py` `SCHEMA` + `validate_dump`). New leaves:
  `tasks[].late_start`, `tasks[].late_finish`, `resources[].calendar_uid`.
  Field counts per scenario: `2 * tasks + resources` more than schema 1
  (recalculate 240→247, link 247→254, task-calendar 246→253, delete 204→209).
* **Task late pair**: MPP14 `+112` LateStart / `+116` LateFinish; MPP12 `+12` /
  `+152`. MEASURED: COM read of `corpus/probe/w3-o1.mpp`
  (`docs/analysis/oracle/w3-o1-open.json`) gives T1 2026-10-26 08:00/17:00,
  T3 13:00/17:00, T4 17:00/17:00, exactly those words. `synthetic-base.mpp`
  uid 2 stores 2026-01-06 13:00 at `+112` while its Start is 2026-01-04 13:00,
  so it is NOT a date copy. `resaved-base.mpp` (Project's own save) keeps the
  values.
* **EarlyStart/EarlyFinish are not separate stored words.** Every COM read-back
  on disk has EarlyStart == Start and EarlyFinish == Finish (32/32
  `w3-o4.json`, 4/4 `w3-o1-open.json`; manual rows too), and `manual-start-edit`
  shows COM Start follows `+104` while `GetField(Start)` is the stale `+96`.
  So the dump's `start`/`finish` (+104/+108) already compare the early pair and
  `calculated_start/finish` (+96/+100) is the calculated copy. Do NOT add
  `early_*` keys: they would duplicate a measured meaning (the brief forbids it).
* **Resource calendar uid is derived, not stored in the resource row.** A
  `TBkndCal/FixedData` row's resource column (`+4` MPP14, `+8` MPP12) names the
  resource; its uid column (`+8`/`+0`) is the calendar. `core/mpp` resolves it
  in `resolve_resource_calendars()` after both tables parse; -1 = no row.
  MEASURED: `w9-resourcetypes.mpp` table (1→3, 2→4, 3→5) == its MSPDI export
  `<CalendarUID>` 3/4/5. A `resource_uid = 0` row exists in every file (null
  resource) and never matches uid 0 (no live resource).
* **Still missing, with the unblocking fixture**: task work/cost (not stored;
  work is assignment-derived), task resume/stop (`+132/+136` candidates only
  correlational — needs a split-task `Task.Stop/Resume` oracle), resource
  rates/cost (no fixture with a non-zero rate), project currency/default task
  type/critical slack limit/week start (all `114/Props`, no measured key; the
  `w3-o4b` CriticalSlackLimit runs were memory-only).

## Traps

* Dump dates are iso with `+00:00`; text search in the C++ self-test needs it.
* Do not write `tests/data/synthetic-base.mpp.json`: `dump_check` derives its
  JSON path from the `.mpp` path, so the fixture dump must go under `build/`
  (the self-test uses `selftest-base.json`).
* The applier intentionally keeps a manual row's stored late pair; the dump now
  compares it, so a manual scenario can fail on `late_*` if Project rewrites
  them on save. That is a measured result, not a dump bug.
