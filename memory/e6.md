# memory/e6 — wave 21

* **mppwrite mirrors the reader's CFB slack rule** (`core/mppwrite/cfb_writer.cpp`
  `CfbDocument::parse`, wave 21): a FAT shorter than the file's sector count is
  a warning (`warnings()`), not a throw; a chain that walks past the FAT still
  throws `"<what>: sector N is past the end of the allocation table"`.
  `sf248.mpp` = 191 slack / 768 FAT / 959 sectors, 81 streams, 0 live tasks;
  `engine_diff_tests --dump corpus\imported\sf248.mpp` exits 0 and prints
  `engine_diff: container warning: …` on stderr.  The JSON is unchanged (all 8
  oracles and the tamper self-check still pass).
* A short-FAT document is **readable but not re-emittable byte-identically**
  (`to_bytes()` derives the FAT from the chains); every round-trip fixture
  covers all sectors, so writer bytes are unchanged; a slack document's
  `check()` says `not round-trippable` and `to_bytes()` refuses (1693 checks).
* `tests/roundtrip_cfb.cpp` has a corpus-free synthetic CFB builder
  (`minimal_cfb`: 3 sectors: directory, FAT, 512-byte stream).  Append 140
  sectors -> warning "15 unreferenced sectors: the FAT describes 128 of the
  file's 143 sectors".  Patch the stream start to sector 130 (exists, no FAT
  entry) -> positioned error.  It also proves a compact CFB re-emits
  byte-identically.
* **constraint-mso is measured, pinned and deliberately left failing** (the

  `docs/engine-parity.md` "Wave 20" is the regression): a manual pinned row with

  non-working saves `+84 = plan duration + remaining standard day windows after

  slack stay the plan's.  `constraint-snet` is the negative control (same

## Traps

* **Dropbox mtime churn**: `edit` refused right after `read` repeatedly.  Re-read
  the exact lines and retry immediately; it then takes.
* **The `read` tool served stale/wrong content once for
  `core/mppwrite/cfb_writer.h`** (it showed a comment block from the `.cpp`).
  When an `edit` says "old_string not found" and the text looks right, verify
  the real bytes with Python (`open(p,'rb')`) before changing the patch.
* Python text writes default to CRLF on Windows: use `newline="\n"` for docs.
* Serial build + redirection only (`cmake --build ... *> build\...\build.log`);
  the first `/W4` build showed C4244 from `std::fill(..., 0xAB)` into
  `uint8_t` — pass `std::uint8_t{0xAB}`.
* Never run `plan_recalc`; it rewrites `tests/data/project_a_recalc_golden.tsv`.
