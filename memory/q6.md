# Q6 memory — the file's stored table (wave 21)

* **The Entry table's stored ids are `...Text` variants**: DurationText `0x0b400507`,
  StartText `0x0b400505`, FinishText `0x0b400506`; the sheet's base fields are
  Duration/Start/Finish.  DurationText is NOT in `make_record_set`, so a stored column
  left on it renders blank.  `app::table_column_field()` owns that mapping.
* **The first `214/CTable` row is the applied task table** in the fixture and both
  corpus files.  `PlanDocument` now keeps the whole `viewstate::TableDef`.
* **The ID column is Project's frozen row-number gutter**, not a scrolling column:
  `display_columns_for_sheet()` skips it and appends the "Add New Column" stub (20
  chars = 123 px).  With that rule the fixture's stored table reproduces the nine
  Entry columns exactly and the parity screen does not move.
* **Store width in characters**: `opaque_header[0]`, px = chars*6+3.  A stored 0 is
  treated as "no width stored" → the stock width; hidden-by-zero is not established.
* **A stored column the app cannot write back is read-only**: only Name/Start/Finish/
  Duration are editable (the save path writes Start pins only).  Do not make the
  others editable — `RecordSet::set_field` would add the field and a save would drop
  it (a fake success).
* **`SheetTableModel` now owns a `std::vector<DisplayColumn>`** (default = Entry,
  loaded = the file's table).  Anything that needs "which column shows field X" uses
  `visible_column_for_field()` (model) or `display_column_for_field()` (display), NOT
  `entry_column_index()` — the Entry index is only valid for the default table.
* **`--render`/`--parity` clears the selection**: Project's measured green
  `#a2d3a0` has luminance ~197, below `parity_report.py`'s `bg-240` rule threshold, so
  a selected row is read as a full-width rule and the 22 px row chain collapses
  (row/header/columns all go "missing").  The render path calls
  `MainWindow::clear_render_selection()`; the interactive window keeps the selection.
* **Menu bar hidden, QActions alive**: `find_action()`-style lookups must keep working;
  `show_backstage()` must not re-show the bar.
* **Task Information**: `DoubleClicked` was removed from the edit triggers; the
  dialog's General tab applies only CHANGED fields (a formatted date such as
  "Mon 19/10/26" does not re-parse, and an untouched field must not fail the apply).
  The gate drives a real `QMouseEvent` double-click and reads the tab titles INSIDE the
  modal loop (the dialog is destroyed on reject).
* **Header captions**: `layout_header_caption()` is the pure wrapping function
  (chevron rect reserved first, 8 px wide 3 px from the right, text starts +4).  Do not
  go back to `TextWordWrap` in a bounding rect — it clipped "Duration" to "Dura".
* **The reader has no new-task scheduling default** (`mpp::ProjectRow` lacks it), so
  the status centre cannot say "Auto Scheduled" for the operator's file.  Recorded,
  not faked.
* **Traps re-paid**: Dropbox mtime churn makes `edit`/`write` refuse; patch files with
  Python (`newline="\n"`).  `QMouseEvent`'s 5-arg constructor is deprecated in Qt 6 and
  `/WX` turns C4996 into an error.  `QAbstractItemView::state()` is protected.
