## (a) What is done

### 1. `core/usage/` — time-phased work buckets (new)

| File | Contents |
|---|---|
| `core/usage/usage.h` | `Period{day,week,month}`, `PeriodSpan`, `enumerate_periods` (day-number and date32 overloads, first/last clipped), `AssignmentInput`, `UsageInput`, `UsageRow`/`UsageTable`, `AssignmentUsage`, `UsageProjection`, `project_usage`, `render_usage_table` |
| `core/usage/usage.cpp` | period enumeration; the flat spread (proportional to the calendar's `work_time_between` ticks, cumulative integer-minute rounding so cells sum exactly); task/resource/assignment projections; name-free rendering |
| `core/usage/usage_mpp.h` | header-only `usage_input_from_mpp(const mpp::Document&)`; maps reader tasks/resources/assignments to the neutral input (packed dates by identity, Work minutes), keeping `core_usage` itself free of a `core_mpp` link dependency |
| `core/usage/CMakeLists.txt` | `core_usage` (links `core_sched` PUBLIC), ctest `usage`, standalone configure branch (adds sched/mpp/cal with their tests off) |

Projection semantics: one period list (union of placeable assignment spans) is
shared by three tables — assignment rows, task rows (sum of that task's
assignments), resource rows (sum of that resource's assignments). Task/resource
tables have exactly one row per supplied uid (reader order); an assignment to a
non-live uid still appears in `assignments` and the total but invents no table
row. Working time comes only from `core::sched::Calendar`, so weekends and
dated calendar exceptions get zero buckets. Work that cannot be phased (NA
dates, finish <= start, zero working time) stays in row/total minutes, adds no
cell, and is counted in `unplaced_assignments`.

### 2. `core/view/resource_tables.h/.cpp` (new, additive)

## (b) What is not done / open

1. **Contour decoding.** `0x0f400031` (planned work steps) and `0x0f400032`
   (actual) are not decoded; every assignment is spread flat. This is exact for
   a contour-less assignment. Shaping a back-loaded/front-loaded contour is the
   next improvement and would be inference until an oracle pairs the step bytes
   with `TimeScaleData` buckets.
2. **Resource calendars / units cap.** One calendar (project) is used; a
   resource's own calendar and `MaxUnits` do not clip or shape buckets.
3. **PROJECT_A has no resource attribution**, so no real corpus file exercises
   resource-usage end to end here. `corpus/probe/assign1.mpp` is the measured
   fixture but is absent (1-byte stub) in this tree.
4. **Week boundary is a decision** (Sunday), not measured. One timescale
   observation would settle it.
