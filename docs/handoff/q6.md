# Q6 handoff — the file's own table, and the operator's four defects

_2026-10-23, wave 21 stream Q6.  No git command was run; the coordinator commits._

## What landed

### 1. Operator decision 7 / build-order step 3 — the loaded file's `214/CTable` table

The task sheet now renders the **column set, order, titles and widths stored in the
file's first `214/CTable` table**.  The fixed Entry presentation is the default only
for a new/empty project (and for a file whose CTable is missing or unreadable).

| layer | change |
|---|---|
| `app/view_model.{h,cpp}` | **new pure API**: `table_column_field()`, `task_column_caption()`, `task_column_editable()`, `table_sheet_columns(const viewstate::TableDef&)` → `std::vector<core::sheet::SheetColumn>`.  Order = `table.columns`; title = the stored UTF-16 title, else a stock caption; width = `opaque_header[0]` (characters); a stored 0 falls back to the sheet's own default width for the field. |
| `app/views_tests.cpp` | `test_table_sheet_columns()` on a **constructed non-Entry `TableDef`** (different order, titles, widths, one unwritable field, one field with no descriptor name): asserts order/titles/widths, the StartText/DurationText→Start/Duration mapping, the caption fallback, the read-only policy, the default-set fallback, and a real `SheetModel` edit+undo through the mapped column. |
| `app_qt/plan_document.{h,cpp}` | keeps the whole parsed `viewstate::TableDef` (caption, date format, columns) instead of the `(field, chars)` pairs; `stored_columns()` = `app::table_sheet_columns(table())`; the SheetModel is built from it (so the MODEL columns are the file's too, not just the display). |
| `app_qt/entry_columns.{h,cpp}` | `DisplayColumn` (title/field/width px/kind), `entry_display_columns()`, `display_columns_for_sheet(SheetModel)`, `display_content_width()`, `display_kind_for_field()`, `EntryCellKind::data`. |
| `app_qt/sheet_table_model.{h,cpp}` | the task-sheet presentation is a live `std::vector<DisplayColumn>` (default = Entry); `columnCount`/`headerData`/`model_column`/`display_kind`/`display_column_for_field` read it.  Generic (resource/usage) mode is untouched. |
| `app_qt/sheet_views.{h,cpp}` | the caption band paints the live presentation's titles/stub; the cell delegate asks the model which column is Task Mode instead of assuming Entry index 1. |
| `app_qt/main_window.{h,cpp}` | `configure_task_columns()` (called from the ctor, `open_file`, `new_project`, `show_view(task_sheet)`), widths from the presentation, the split snap to the live table's width, the initial selection on the field's Name column, delegate kind lookup. |

**How a stored column maps** (`app::table_sheet_columns`):

| stored `214/CTable` field | sheet field | editable? |
|---|---|---|
| `0x0b400017` ID | ID | no — identity (the frozen row-number gutter draws it) |
| `0x0b4000cd` Indicators | as stored | no — no RecordSet value, caption stays empty |
| `0x0b400500` Manual (Task Mode) | as stored | no — the delegate paints the pin |
| `0x0b40000e` Name | Name | **yes** |
| `0x0b400507` DurationText | **Duration** `0x0b40001d` | **yes** |
| `0x0b400505` StartText | **Start** `0x0b400023` | **yes** |
| `0x0b400506` FinishText | **Finish** `0x0b400024` | **yes** |
| `0x0b40002f` Predecessors | as stored | no — no decoded text |
| `0x0b400030` Successors | as stored | no |
| `0x0b400031` Resource Names | as stored | no |
| `0x0b400020` PercentComplete | as stored | no |
| anything else | used as-is | no (unless Name/Start/Finish/Duration) |
| field id `0` | skipped — not a column | — |

The three **…Text → base** mappings are required, not cosmetic: the Entry tables
store DurationText/StartText/FinishText, and DurationText has no RecordSet column at
all, so an unmapped Duration column would render blank.  Those three base fields are
also what `make_record_set()` fills, `sync_plan_from_records()` reads back and the
writer saves.  The mapping is an inference (measured text-variant ids in
`114/Props`/CTable, plus the registry's own Entry columns use the base ids) — see
docs/handoff/w51.md and memory/props.md.

**Display vs model**: the display skips the ID column (Project draws it as the frozen
row-number gutter, `SheetRowHeader`) and appends "Add New Column" (a shell
affordance, not stored; 20 chars = 123 px).  Every other stored column, in file
order, is a display column.  For the committed fixture this is **exactly** the nine
Entry columns, which is why the parity screen does not move.

### 6. Earlier items — header captions and "Ready"

* `sheet_views.{h,cpp}`: new **pure** `layout_header_caption()` (lines + text rect +
  arrow rect).  The chevron rect (8 px, 3 px from the right edge) is reserved

  intersect the arrow; a single-word caption is never shortened.  The band paints

  message in the left slot.

## Verified vs inferred

**Verified by running** (all quoted above): the app function's order/title/width and
read-only policy on a constructed table; the sheet model edits/undo through a mapped
column; the Qt window's display on the Entry fixture, on a synthetic non-Entry file
through `open_file`, and on `corpus/project_a.mpp` (titles `""/Task Name/Dur/Start/
Finish/% Complete/Pre/Suc/SUMMARY/Add New Column`, widths
39/423/57/117/129/45/81/81/105/123); the 14 Qt gates; parity 9/0; the app suite.

**Inferred, not measured here**:
* the width byte is characters (pre-existing inference, wave 14/18);
* the StartText/FinishText/DurationText→base mapping (measured ids, inferred pairing);
* the caption table for fields the descriptor table does not name (Indicators stays
  blank, Task Mode/Predecessors/Successors/Resource Names/% Complete come from the
  PJINTL table resource and the reference capture);
* a stored width of 0 means "the file stores no width" — *hidden-by-zero* is not
  established, so it falls back to the stock width rather than hiding the column;
* the ID column is the gutter (observable in every capture, not a stored flag).

## Gaps / not done

1. **New-task scheduling default**: `mpp::ProjectRow` exposes no
   new-task/Auto-Scheduled field, so the status centre still says
   "New Tasks : Manually Scheduled" on a loaded file even though the operator's
   83-task file is Auto Scheduled.  **Not faked** — it needs a reader field or a
   decision; recorded for wave 22.
2. A stored column whose field the RecordSet does not carry (Indicators,
   Predecessors, Successors, Resource Names, Summary/Flag10 on the corpus file)
   renders **blank and read-only**.  Decoding those texts is not in this wave.
3. Only **Start** edits are written by a save (pre-existing: `save_date_edits`); a
   Name/Duration/Finish edit on the sheet still changes the model and undo but is not
   written.  Task Information inherits that behaviour.
4. Task Information's five non-General tabs are laid out-only (decision 15); General's
   Estimated/Percent/Priority/Schedule mode/Timeline options have no writer.
5. `--render`/`--parity` clears the cell/row selection: the measured green band has a
   luminance below P1's rule-scan threshold and would be read as a grid rule.  The
   interactive window keeps the selection (gated by `qt_ux_gate`).
6. The header band's physical text baseline moved (the lines are now painted by the
   layout function); the parity measures are unchanged, but a future pixel-diff
   report may show the caption shift.
