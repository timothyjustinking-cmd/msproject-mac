## 3. Corpus `214/CEdl` -- a cumulative Props-document cache

### 3.1 Measured shape (`build/w62/scratch/dump-corpus/214/CEdl`)

`Var2Data` is 9,932 B; `VarMeta` declares 2 entries and `var2_size = 9932`.
A strict walk finds 8 documents and then fails at 7,780:

```
block  0      length  964   document 964   (14 records)  view "&Gantt Chart" table "&Entry"
block  968    length  508   document 504   (12 records, format word 0x00019f07)
block  1,480  length 1,028
block  2,512  length 1,036
block  3,552  length 1,044
block  4,600  length 1,048
block  5,652  length 1,056
block  6,712  length 1,064
        7,780  u32 = 10,846  <-- only 2,148 B remain: strict walk refuses here
block  7,784  length 1,068   document 1,068 -> ends 8,856
block  8,856  length 1,068   document 1,068 -> ends 9,928   (VarMeta uid 1)
        9,928  4 bytes  ff ff ff ff
```

`VarMeta`: `uid 6 -> 968`, `uid 1 -> 8,856`. So the last document is the live
one; the earlier nine are older saves of the same current-view document (same
`&Gantt Chart` / `&Entry`, growing record sizes). `project_b` is the same shape
with only 3 documents and no residue: blocks at 0, 786, 1,296; VarMeta
`uid 6 -> 786`, `uid 1 -> 1,296`; 2,326 B.

The two 4-byte runs are stale values, not a directory: `0x2a5e` is a value from
the `0x26400024` field-id list family, and `0xffffffff` is the terminator shape
of a `0x26400017` field list.

### 3.2 The rule (implemented, `parse_var2_edl_cache`)

1. At the current offset, a u32 is a block iff it fits the remaining bytes **and**
   its payload parses as a complete Props document (`props::parse_props`).
2. Otherwise skip 4 bytes (at most `kEdlCacheMaxResidue = 8`) and retry; the
   skipped bytes become a `Var2Gap`.
3. After the last block, up to 8 trailing bytes are kept as a gap.
4. Every `VarMeta` entry offset must be one of the discovered block starts.

`parse_var2()` itself is unchanged, and `parse_view_state()` only falls back to
the cache rule for class `"CEdl"`. A failed cache parse returns the cache error,
not the old generic one. The encoder writes gaps back in stream order, before the
block that followed them, so a no-op encode is byte-identical. `--roundtrip` on
both corpus trees now reports `CEdl` byte-identical (9,932 B and 2,326 B).

### 3.3 What the corpus CEdl now decodes

The live document at 8,856 decodes with the existing typed path:
`view="&Gantt Chart"`, `table="&Entry"`, `field-list=9` ids
(`cd00400b 0e00400b 0705400b 0505400b 0605400b 2000400b 2f00400b 3000400b
5100400b`, no terminator). All ten documents decode as Props documents.

`--regenerate-edl` on the corpus tree **still refuses**, now precisely:

```
viewstate_report: regenerate_edl refused: CEdl applied table "&Entry" does not
resolve to exactly one decoded table
```

The corpus CTable has two tables whose name is `&Entry` (task Entry uid 1 and
resource Entry uid 4). Resolving that needs a task/resource discriminator the
CEdl does not expose in a decoded record; it is *not* a cache-parse problem.
Regeneration on the synthetic family is unchanged.

## 4. `214/CFilter` -- block criteria framing and the `...0007` record

Measured on **53 blocks** in the 14 trees that carry a CFilter (12 synthetic
fixtures + both corpus files):

```
+0  u32  row ordinal (== FixedData +0 == VarMeta uid)
+4  u32  flags/format: 0x100 on every synthetic block and on corpus rows
         18/19; 0 or 1 on the other corpus rows.  Meaning NOT established.
+8  u16  0
+10 u16  0
+12 u16  0
+14 u16  criterion record count N
+16 u32  string-table offset S: S == 20 + 36*N on 53/53 blocks
+20      N * 36-byte criterion records
+S       NUL-terminated UTF-16 strings: applies-to kind first
         ("tasks"/"resources"), then prompts ("Group name:", "Enter Task Name
         Here", "Summary")
```

Criterion record: `+0 u32 tag`, `+4 u32 operator index`, `+8 u32 field id or 0`,
other 24 bytes opaque. Tags measured: `0x0b` (first record of every block),
`6`, `7`, `1`, `0x19`, `0x1a`, `0x1c`, `0x27`, `0x3ed`, `0x3ee`, `0x3ef`.
Tag `7` is a field test: **40/40** of its `+8` words are plausible property ids
(`0x0b40xxxx` / `0x0c40xxxx`), cross-checked against CTable column ids
(`0x0b40000e` Task Name, `0x0b400018` Milestone, `0x0b400021` Predecessors,
`0x0b400033` Text1, `0x0b4004ff` Active, `0x0c400003` Resource Group).
**Opaque:** which operator value means "contains", how the operand records pair
with the tag-7 tests, and the other 24 bytes of each record. Everything is
copied verbatim.

The `...0007` row record (row record set, relative offset from `row + 0x6e`):

```
+0 u16  a word: 0 in all 30 measured rows that carry the record
+2      optional NUL-terminated UTF-16 label
```

20 of those 30 rows have a non-empty label and it equals the `...0009` display
name in all 20. The other 10 are exactly 2 bytes (corpus rows 9..11 are three of
them); corpus rows 23/24 carry `00000000` (word 0 + empty label). **No criterion
is stored in `...0007` in any measured file** -- the criteria are in the block.

New fields: `FilterDef::{block_flags, criterion_count, string_table_offset,
criteria_decoded, string_table, criteria_record_decoded, criteria_record_word,
criteria_record_label}`.

## 5. `214/CGrouping` -- header named, body opaque

Measured on 5 blocks (2 synthetic "No Group" rows, corpus uids 9/10/11):

| shape | size | +4 flags | +8 | +10 | body |
|---|---|---|---|---|---|
| synthetic "No Group" | 83 | 0 | 0x100 | 0 | 71 zero bytes |
| corpus "No Group" (uid 9, 10) | 12 | 0 | 0x100 | 0 | absent |
| corpus "Status" (uid 11) | 83 | 0x100 | 0 | 1 | 71 bytes, first u32 `0x0b40021f` |

+0 is the row ordinal in every block. So a **12-byte block is the measured "no
stored definition" shape**, and the 83-byte body is opaque; the only body field
named is the first u32 when it is a plausible property id
(`GroupingDef::body_field_decoded/body_field_id`). No grouping-key semantics are
claimed.

`0x2240001d` / `0x22400038` in CV_iew are **not view geometry**: corpus view 1
(Gantt Chart) carries `0x2240001d = 090000000000000000010000`, byte-identical to
the CGrouping block of uid 9 ("No Task Group"). They are caches of the applied
definition; nothing writes them. `0x2240001f` is the 2-byte criterion word
(matches the `...0007` word, 0 in every view).

## 10. Traps

- **Do not "fix" `parse_var2` globally.** The cache rule is CEdl-only and the
  cache path validates Props documents and VarMeta; applying it to every class
  would make corrupt streams parse.
- **The residue is part of the stream.** The encoder must write gaps back before
  the following block; rebuilding Var2Data from blocks alone loses 8 bytes on
  `project_a`.
- **`replace_block_payload` must shift gap offsets too** (added in this stream);
  a regenerated live document moves the trailing residue.
- **The corpus CEdl's live document is not the first block.** It is the block
  VarMeta names (uid 1 -> 8,856 in `project_a`); `regenerate_edl` already picks
  it by the first FixedMeta row's ordinal.
- **`CEdl applied table "&Entry"` is ambiguous in the corpus** (task and
  resource Entry tables). Do not relax table resolution to "first match" to make
  regeneration succeed; that would write the wrong field list.
- **CFilter criteria are in the block, not in `...0007`.** The row record's
  first u16 is 0 in all 30 measured rows.
- **CFilter `+4` is not the criterion count.** The count is the u16 at `+14`;
  the string-table offset at `+16` must equal `20 + 36*count`.
- **`0x2240001d`/`0x22400038` are definition caches**, not splitter or row
  geometry; they are byte-equal to CGrouping blocks.
- **A full-tree build is currently red for other streams' files** (see §8); build
  the viewstate targets, and never `--parallel`.
