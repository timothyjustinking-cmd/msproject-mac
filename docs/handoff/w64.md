# W64 handoff -- wiring the `214/CTable` and `114/Props` writers into the app save pipeline

Date: 2026-10-23. Owner: stream W64 (wave 15). Status: **delivered** -- the two
save operations, their integration seam, ten new `document_tests` cases and the
build wiring. No git command was run. Files outside this stream's lane were
touched only for the three authorised `app/CMakeLists.txt` lines (section 3).

## 1. Result

The app's save pipeline can now persist, on one `mppwrite::CfbDocument`, and in
one container write:

1. a **`214/CTable` view-state edit** -- the date-format byte or a
   replacement of one existing 115-byte column record, through
   `core/viewstate`'s `parse_view_state` / `set_table_date_format` /
   `set_table_column` / `encode_view_state`; and
2. a **custom-field formula** -- set one Task field's formula, or clear the whole
   formula table, in `114/Props`, through `core/props`'s
   `set_custom_field_formula` / `clear_custom_field_formula`, with the measured
   `0x02401392` "custom-field data in use" flag repaired to **1** when the
   project still stores a custom-field value.

No pending edit means no change: a no-op save writes the source container
**byte-for-byte** (asserted in a test, `214/` included). A refused view-state
request is a warning; the save still succeeds and `214/` stays byte-identical.

## 4. API

```cpp
namespace app {

struct ViewStateEdits {
    bool set_date_format = false;
    std::uint8_t date_format = 0;      // 0xff default; 0x05 = DateFormat 5 (measured)
    bool replace_column = false;
    std::uint32_t column_index = 0;    // an EXISTING column (append is not measured)
    std::uint32_t field_id = 0;
    std::string title;                 // printable ASCII, <= 51 code units
    std::uint32_t table_index = 0;
    bool any() const noexcept;
};

struct CustomFormulaEdit {
    enum class Operation { none, set, clear };
    Operation operation = Operation::none;
    std::uint32_t field_id = 0;
    std::string formula;
    bool any() const noexcept;
};

struct DocumentEditOutcome {
    bool ok = true;                    // false = a FORMULA refusal; do not save
    bool view_state_written = false;
    bool formula_written = false;
    bool custom_field_flag_restored = false;
    std::vector<std::string> warnings; // a refused view-state edit lives here
    std::string error;
};

DocumentEditOutcome apply_document_edits(mppwrite::CfbDocument& document,
                                         const ViewStateEdits& view,
                                         const CustomFormulaEdit& formula);

class Document {
  public:
    explicit Document(std::string source_path);
    void request_view_state_edits(const ViewStateEdits&);
    void discard_view_state_edits();
    bool apply_custom_formula(std::uint32_t field_id, std::string_view formula,
                              std::string* error = nullptr);
    void clear_custom_formula();
    void discard_custom_formula();
    bool has_pending_edits() const noexcept;

    SaveOutcome save(std::string_view target_path, const SaveOptions& = {}) const;
    SaveOutcome save(const std::vector<StartEdit>& start_edits,
                     std::string_view target_path, const SaveOptions& = {}) const;
};

}  // namespace app
```

`SaveOutcome` gained `view_state_written`, `formula_written`,
`custom_field_flag_restored` (all false for a plain date-only save).

## 5. Pipeline order (the part a successor must not reorder)

```
link deletes -> link adds -> task deletes -> task inserts
             -> custom-field VALUES (save_field_values / clear_field_value)
             -> [W64] formula (114/Props)
             -> [W64] view state (214/CTable)
             -> ONE container save (save_date_edits / CfbDocument::save)
             -> check_table
```

- The formula step must follow the field-value writers: the `0x02401392` flag is
  shared, and whether it must stay 1 depends on the values the table writers
  just produced. `apply_document_edits()` is designed to be called on the
  `CfbDocument` those writers already own, immediately before the final save.
- The two operations cannot invalidate a row/table index, so running last keeps
  every earlier writer's own post-save re-read proof valid.
- `Document::save(start_edits, target)` is the convenient case for a save that
  has ONLY start pins plus these two operations: it applies the formula/view
  state to the in-memory document and then runs `mppwrite::save_date_edits` on
  that same document, so `save_date_edits`'s "every other stream unchanged"
  check takes the already-replaced `114/Props`/`214/` streams as its baseline.
  The stream sets are disjoint; one write, same result as dates first.
- A save with field/link/structural edits is NOT covered by `Document`; call
  `apply_document_edits()` inside the existing cascade (`app/edit_model.cpp` is
  not this stream's lane).

## 6. What is written, byte-wise

### 6.1 `214/CTable` (date format)

Read `214/CTable/{FixedData,FixedMeta,VarMeta,Var2Data}` from the
`mppwrite::CfbDocument`, `parse_view_state("CTable", parts, state)`, apply
`set_table_date_format(state_copy, table_index, date_format)`, re-encode with
`encode_view_state`, then replace each of the four streams whose bytes changed
with `CfbDocument::replace_stream`.

Measured fixture (`tests/data/synthetic-base.mpp`): one 1047-byte CTable block at
Var2Data offset 0, date-format byte 0xff at stream byte 11 (block payload +7),
9 columns. Setting 0x05 changes exactly stream byte 11; FixedData, FixedMeta and
VarMeta are byte-identical, and every other `214/` stream is byte-identical.
Test: `test_save_view_state_date_format`.

**Surface note (asked for in the brief).** `core/mpp/cfb.h` is a
**read-only** container reader: it has no "replace a stream's bytes" API at all.
The write therefore goes through `core/mppwrite`'s `CfbDocument::replace_stream`
(the narrowest existing surface; it reuses the stream's sectors when the size
fits and appends fresh sectors when it grows). `core/mpp/reader.*` was not
touched.

### 6.2 `214/CTable` (column replacement)

`set_table_column(state_copy, table_index, column_index, field_id, title)` on the
same copy, then encode and replace only changed streams. Index 1 of the Entry
table is replaced with Text1 (`0x0b400033`, title "Text1"): the 115-byte record
at absolute Var2Data bytes 131..245 changes, its field id and zero-filled title
change, the 9 opaque bytes are preserved by the writer, the column count stays 9
and `last_column_index` stays 8. Test: `test_save_view_state_column`.

Both edits are applied to a **copy** of the parsed `ViewState`: if either mutator
refuses (e.g. column index 99), neither edit is encoded and `214/` is untouched
(test `test_save_refused_view_state`: save succeeds, warning
"view state not written: column index 99 is out of range (9 column(s))",
`214/` byte-identical).

### 6.3 `114/Props` (formula set)

Read `114/Props`, call `props::set_custom_field_formula(props, field_id,
formula, updated)`, replace the stream. W59's writer already writes flag 1 and
only touches the formula record + the flag. Test `test_save_formula_set`:
Text2 = `[Name]` reads back through `props::extract_formulas` as
`[MSPJ188743694]` / `[0x0b40000e]`, flag 1; every `214/` stream unchanged.

External re-check (not part of ctest) on the written file's extracted
`114/Props`:

```
props_report --formulas build\w64-scratch\formula-props.bin
-> formulas: 1  field=0x0b400036 ... formula=[0x0b40000e]
props_report --dump ... | 0x2401392 -> hex:01 00
```

### 6.4 `114/Props` (formula clear) and the `0x02401392` rule

Read the stream and parse it. If `extract_formulas()` is empty the clear is a
**no-op that rewrites nothing** (so a value-only project's flag is untouched).
Otherwise call `props::clear_custom_field_formula`, then:

- if the document still stores a custom-field **value**, patch the flag record
  (kind 2, length 2) payload back to **1**;
- if it does not, keep the writer's **0**.

Value detection (`custom_field_value_remains`, `app/document.cpp`) reads the
task table the document knows:

1. any `114/TBkndTask/VarMeta` key that is a measured Task custom-field id
   (`mpp::custom_field_kind != unknown`, i.e. Text/Flag/Number/Duration/Cost/Date);
2. any set Flag1 bit (`entry +24 & 0x02`) in a task row's FixedMeta entry
   (entries 3.. declared: Task FixedMeta starts with 3 non-task entries; Flag1 has
   no VarMeta block, the bit is the value);
3. any `114/TBkndAssn/VarMeta` key at or above `0x0f40403c` (the measured
   assignment custom-key base, W60).

A table that cannot be read answers "yes" (keep the flag 1): that is the safe
direction. A cleared field keeps a stale VarMeta entry (W52), so the predicate
can stay true after a value clear; that is deliberate and conservative.

**Why a raw patch.** `core/props` has no public "set the flag" API: W59 owns it
only as a side effect (set -> 1, real clear -> 0) and its handoff explicitly says
the app must restore it. This stream parses with `props::parse_props`, requires
the record to be the measured kind 2 / length 2, and writes the two payload bytes
at `record.offset + 12`; no size word, record or tail changes. A future core
stream could add `props::set_custom_field_flag()` and delete this patch -- that is
the one clean core change we would have liked and did **not** make.

Tests:

- `test_save_formula_clear_with_values`: formula on Text2, then Text1 = "alpha"
  through `mppwrite::save_field_values`, then clear. Result: `props_report`
  shows the 8-byte empty formula record and `0x2401392 = 01 00`; the reader still
  returns Text1 "alpha"; `SaveOutcome::custom_field_flag_restored` is true.
- `test_save_formula_clear_value_free`: clearing the empty table on the stock
  fixture rewrites nothing, `114/Props` is byte-identical and the flag is
  `00 00`.

## 8. Proved vs inferred, and what only `app-macos` can prove

**Proved on this box (test + re-runnable command):**

- the four `214/CTable` parts survive `parse -> mutate -> encode` with only the
  requested byte/record changed (for the measured fixture);
- a refused view-state edit leaves `214/` untouched and does not fail the save;
- a save with nothing pending writes an identical container;
- `114/Props` is rewritten only for a real formula change; set writes the
  measured token and flag 1; clear writes the 8-byte empty table and the flag is
  1 with a remaining Text1 value, 0 without one;
- the date + formula + view-state save composes through
  `mppwrite::save_date_edits` in one write;
- `CfbDocument::replace_stream` round-trips the written container
  (`reread.to_bytes()` equals what was written, checked in `Document::save`);
- every other app test still passes.

**Inferred / not proved here:**

- that **MS Project accepts** a file with these rewritten streams. The mutations
  are the wave-14 oracle's measured edits (docs/analysis/oracle/w14-oracle.md
  section 1; W59's formula record is byte-identical to Project's own save), but
  no `.mpp` containing W64's output has been opened in Project. COM is
  coordinator-only.
- the value-detection predicate's *completeness*: it reads the measured Task and
  assignment stores; an unmeasured custom-field store would be missed (it errs
  towards keeping the flag only when it cannot read a table at all).
- `table_index` other than 0: the measured fixtures have one CTable table; the
  API passes the index straight to `core/viewstate`, which refuses an out-of-range
  table.
- replacing a column with a *longer* title, a non-ASCII title, or changing a
  column's width/format (all refused or not offered by `core/viewstate`).

**Only `app-macos` can prove:** that the shell calls this API at the right point
in its save (the `main.mm` wiring is W63's lane and was not exercised here), that
the AppKit save panel/close-prompt path still behaves, and that a real Mac build
of `main.mm` compiles against the new `Document` class. No project file has been
re-opened in MS Project by this stream.

## 10. Traps

- **The Dropbox folder's mtime churn defeated the `edit`/`write` tools again**
  ("file changed since it was read", even right after a read, including on files
  created in this session, and one transient `PermissionError`). Workaround:
  write `<file>.new` with the full content, then `Move-Item -Force`; or a Python
  script that asserts every anchor's `count == 1` before writing. The helper
  scripts live in `build\w64-scratch\` (build tree, never committed).
- **Two writers share one stream set.** `core/viewstate` refuses to append a
  column; `core/props` cannot see the task table. Do not "fix" either by growing
  the block or guessing the flag: the app applies both edits to a copy and only
  writes when the writer accepted them.
- **The flag is not a formula count.** `0x02401392` is 1 for a project with
  values and no formulas (W59 table). A clear that ignores the task table turns
  Project's custom-field UI off for a project that still has values.
- **Formula first, view state second** in `apply_document_edits`: a formula
  refusal must not leave a view-state replacement in a document the caller then
  refuses to save.
- **`save_date_edits` checks "every other stream unchanged" against the document
  it is given.** `Document::save(start_edits, ...)` replaces `114/Props`/`214/`
  first, so those streams become its baseline; this is why the combined save is
  one write and still passes W37's proof.
- **`APP_MPPWRITE_SAVE_HEADER` is 1** in this tree; the `#else` date path
  (`pin_task_start`) is kept compiling but is not what the tests exercise.
