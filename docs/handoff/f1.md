## 3. The row record set at `row + 0x6e` (new, and a correction to W56)

Every 230-byte FixedData row (`CTable`, `CFilter`, `CGrouping`) carries an
inline record set:

```
row + 0x6e (110)  u32 set size (set ends at row + 0x6e + size; 0 = no set)
row + 0x72 (114)  u32 record count
row + 0x76 (118)  count * { u32 id, u32 payload_offset relative to row + 0x6e }
                  payloads, in record order
```

Measured on `build/dump-base`:

| class | row | size | count | entries | name at |
|---|---|---|---|---|---|
| CTable | 1 (`&Entry`) | 38 | 2 | `0x20400007@24`, `0x20400009@26` | +136 |
| CFilter | 1 (`&All Tasks`) | 46 | 2 | `0x20400007@24`, `0x20400009@26` | +136 |
| CGrouping | 1 | 54 | 2 | `0x2d400007@24`, `0x2d400009@26` | +136 |
| CGrouping | 2 | 52 | 1 | `0x2d400009@16` | +126 |

`...0009` is the row's display name without the accelerator; `...0007` is the
criteria blob and stays opaque.  The set is validated on every synthetic tree
and on the corpus file (CTable 8/8 rows, CFilter 16/16, CGrouping 3/3; rows
with size 0/count 0 are the measured "built-in, no stored definition" shape).

**W56's "second UTF-16 caption at +136" is this record set's name payload.** For
a task-shaped set the name sits at relative 26, i.e. row + 136; for a
name-only set it sits at relative 16, i.e. row + 126.  The old +136 read
therefore produced tails such as `"esources"` / `"sk Group"` on corpus rows
whose set has count 1.  `FixedRow::display_caption` now comes from the record
set, with the old +136 read kept only as a fallback for rows with no set (and
for `CDrawing`, whose 230-byte rows are not a record set -- its bytes at +0x6e
are garbage and are not parsed).

## 4. `214/CEdl` -- typed record set and `regenerate_edl`

### 4.1 Measured document layout (`build/dump-base`, block payload 470 B)

```
Var2Data +0      u32 470                                  (block length word)
Var2Data +4      Props document (470 B, 14 records, no tail)
  doc +0         u32 466                                   stream_size - 4
  doc +4         u32 466
  doc +8         u32 0x00010000
  doc +12        u32 14
  doc +52        record header 0x26400018, payload at doc +64, 26 B   "&Gantt Chart"
  doc +90        record header 0x26400019, payload at doc +102, 12 B  "Entry"
  doc +114       record header 0x26400017, payload at doc +126, 36 B  field list
  doc +436       record header 0x26400031, payload at doc +448         opaque host path
                 (only in Project's re-save; absent from the gate file)
```

The field list at `doc +126` is `8 ids + 0xffffffff`:
`cd00400b 0005400b 0e00400b 0705400b 0505400b 0605400b 2f00400b 3100400b ffffffff`
(Entry columns 1..8, then the terminator).

Record ids are order-independent (Project's re-save moved `0x2640003d` before
`0x26400024` and appended `0x26400031`); the typed decoder searches by id.

### 4.2 What `regenerate_edl(state, from_table_state)` writes

| record | value | evidence |
|---|---|---|
| `0x26400018` | applied view's `FixedData` caption | CEdl "&Gantt Chart" == CV_iew row 2 caption in `dump-base` |
| `0x26400019` | applied table's display name (`display_caption` when non-empty, else `caption`) | "Entry" == the CTable row's record-set name; "W14 Entry C" == the created table's caption (no `&`); corpus keeps "&Entry" because its row has no display name |
| `0x26400017` | applied table's `columns[1..]` field ids, keeping `0xffffffff` only when the existing record had it | base 9 columns -> 8 ids + terminator; tablecol-C 9 columns -> 8 + terminator; w15proj 10 columns -> 9 + terminator; flags-2 fixtures (A/B/I/J/K) have no terminator |

Applying the view's applied table: `from_table_state.find_related("CV_iew")`
first; the view is resolved from the CEdl view name (exact, then
accelerator-insensitive, then display name, then the single view that applies
the CEdl table name, then the only single view).  The table is resolved from
that view's `0x2240000a` name against the CTable rows (accelerator-insensitive;
refuses if zero or more than one match).  Without a linked CV_iew the view-name
record is left alone and the table comes from the CEdl record's own name.

The embedded document is rebuilt: record order/ids/kinds, header
`format_version`/`declared_entries`, the tail and the input's size-word delta
(`stream_size - 4` on both measured variants) are preserved; only the three
target payloads and the two size words change.  The Var2Data block length word
is re-written and every later block / VarMeta offset / decoded block offset is
shifted.  No host path is ever fabricated.

`set_view_table` re-frames the item (u32 length at `header +0`, u32 id `+4`,
u32 kind `+8`, UTF-16 text `+12`, one pad byte when `12 + length` is odd),
updates the block's two size words (`payload +0`, `payload +4`), the u32 block

VarMeta offset and every decoded `ViewDef::main_block_offset`, then re-decodes
the block.  On the two-view test fixture "W14 Entry C" grows the item by 10
bytes, so the second view's block moves +10 and its `0x2240000a` still reads
"&Gantt Chart".

`set_view_name` does **not** touch `0x2240002a` (the display name): the
measured caption/display pair is not derivable (synthetic view 1 stores
`"Gantt &with Timeline"` but displays `"Gantt Chart with Timeline"`), so the
writer refuses to guess.  The caption-only change is tested to be confined to
the 118-byte caption area and to re-parse.

`set_view_page_margins` writes four u32 at the `0x22400009` payload start; on
the test fixture `500 -> 720` changes exactly 8 bytes (two per u32) inside the
16-byte margin block.

Refusals (all leave every part unchanged, tested): bad view index, undecoded
main block, missing `0x2240000a`, missing 970-byte `0x22400009`, empty /
non-ASCII / over-capacity names, margin > 100000, a non-CV_iew state.

## 7. The seam

```cpp
bool regenerate_view_state(ViewState& state, const TableEdits& edits,
                           WriteError* error = nullptr);
```

`state` is a parsed `214/CTable`.  The seam copies it, applies the edits in
order through the three existing mutators, then:

- linked `"CEdl"`: `regenerate_edl()` against the edited table;
- linked `"CV_iew"`: validated and left **byte-identical** (no measured
  TableEdit derives a view name, table reference or margin);
- linked `"CFilter"` / `"CGrouping"`: validated and left byte-identical;
- links are `ViewState::related` (`std::vector<ViewState*>`, non-owning, never
  parsed or encoded).

Commit happens only after every step succeeded; on failure `error` names the
edit index or the class and no state is modified.  Without links the seam is an
in-place table edit.  Tested: append -> CTable 10 columns, CEdl 9 ids,
CV_iew byte-identical, table bytes equal `apply_table_edits`, re-parse clean;
a failing second edit leaves CTable and CEdl untouched.

## 10. Corpus `214/CEdl` is not a strict Var2Data block walk (new finding)

`build/w62/scratch/dump-corpus/214/CEdl/Var2Data` is 9,932 bytes and its
VarMeta declares `var2_size = 9932`, but the walk finds only **8** framed blocks
(offsets 0, 968, 1480, 2512, 3552, 4600, 5652, 6712).  At 7780 the u32 is
`0x2a5e` (10,846) with only 2,148 bytes left, so `parse_var2` refuses:
`Var2Data block at 7780 declares 10846 payload bytes but only 2148 remain`.
The remaining 2,152 bytes look like a cache directory/footer (`0x2a5e`,
`0x042c`, `0x0428`, `0x0428`, `0x014258`, `0x0e` ...), not a block.  The W62
binary refuses the same stream, so this is not a regression: no corpus CEdl
round-trip or regeneration is possible with the strict walk, and the synthetic
CEdl family is the measured scope.  (The corpus CEdl also uses Props format
`0x00014258`, two fixed rows and nine blocks, versus the synthetic
`0x00010000`, one row and one block.)

This does not affect the corpus CTable/CV_iew/CFilter/CGrouping checks: those
parse and decode (see §8), and `CV_iew/Var2Data` at 1,022,179 B is still
byte-identical.

## 11. Traps

- **The record set is not the +136 caption.**  Task-shaped sets put the name at
  relative 26 (= row + 136); name-only sets put it at relative 16 (= row + 126).
  Reading +136 unconditionally yields `"esources"` / `"sk Group"`.
- **`CDrawing` is a 230-byte-row class too**, but its +0x6e bytes are not a
  record set; parsing them produced "declares 4044484190 records" warnings and
  was gated by class.  Do not generalise the set to every 230-byte row.
- **Two `klass` shadowing traps**: a member function parameter named `klass`
  in `ViewState` methods is C4458 under `/W4 /WX` (hit in this stream; renamed
  `wanted_klass`).  `block_kind` / `is_known_class` / `parse_view_state` are
  free functions, so `klass` is fine there.
- **CEdl record ids are not in a fixed order.**  Project's re-save reordered
  records and appended the host record; search by id, never by index.
- **The CEdl header size words are `stream_size - 4`, not `stream_size`.**  The
  rebuild preserves the input's delta; on both measured variants the delta is 4.
- **`replace_block_payload` shifts three decoded offset sets**: every later
  `VarBlock::offset`, every `VarMetaEntry::offset` and the decoded
  `TableDef::block_offset` / `ViewDef::main_block_offset` /
  `EmbeddedProps::block_offset`.  Miss one and a second edit/encode fails.
- **A view's caption is not its display name.**  `"Gantt &with Timeline"` vs
  `"Gantt Chart with Timeline"` is a measured counter-example; do not derive one
  from the other.
- **Item padding**: `set_view_table` pads `12 + payload` to even; building the
  new item without the pad breaks the item walk on the next item.
- **Corpus CEdl is not a block walk** (§10); do not "fix" `parse_var2` to accept
  it without measuring the trailer's layout.
- `ctest` needs vcvars; this stream's build directory is `build\f1`; never
  `--parallel`.
