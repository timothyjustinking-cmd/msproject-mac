## Which columns now show values, and how

All three computed texts go into the **RecordSet** under the field id the stored
column already carries, and the existing model/delegate path paints them — no
special case in the view layer.  `PlanDocument::fill_computed_columns()` runs at the
end of `build_gantt()`, i.e. after `view_ = app::sync_plan_from_records(...)`, so a
structural Predecessors edit re-derives the text in the same rebuild.

### Predecessors (`0x0b40002f`) — **now renders**
`predecessors_text(plan, uid, format)`: one entry per link whose **successor** is
the task, in the file's link order, joined with `,` (no space):

* other endpoint printed by its **Task ID** (not UniqueID);
* the type letters are **dropped only for a lag-free FS link** (`4`);
* a lagged FS link keeps `FS` and the signed lag (`9FS+50 days`);
* `SS`/`FF`/`SF` always print (`33SS`);
* lag text is the signed stored tick count through **the sheet's own duration
  formatter**;
* a link whose other endpoint has no live task row is skipped; an unknown uid
  returns `""`.

### Successors (`0x0b400030`) — **now renders**
The same function from the other end (one entry per link whose **predecessor** is
the task), same syntax and same order rule.

### % Complete (`0x0b400020`) — **was already showing the value, now shows Project's text**
The stored percent was already in the RecordSet, so the column showed `57`, `100`,
`29` (matching the coordinator's render).  Project's own column reads `57%`,
`100%`, `0%`, so `PlanDocument::stored_columns()` now declares that column
`core::sheet::CellKind::Percent`.  The change is in the model's format, not in a
painter, so the clipboard and every other consumer see `57%` too.

### Resource Names (`0x0b400031`) — **implemented, blank on both files (byte reason below)**
`resource_names_text(plan, uid)`: each assignment row for the task that names a
resource, mapped to the resource's display name, `, ` separated (Project's list
convention).  A row that names nothing, names an unknown resource, or names a
nameless resource contributes nothing.

## Which columns cannot be sourced, and the exact byte reason

### `SUMMARY` = `Task.Flag10` = `0x0b400051` — blank
* The value **is** in the file (Project's capture renders it), but as a **bit in the
  Task `FixedMeta` entry**, not as a `Var2` value.
* The reader decodes **exactly one flag bit**: `Flag1 = 0x0b400048` at Task
  `FixedMeta` entry **byte +24, bit `0x02`** (`core/mpp/reader.cpp`
  `kFixedMetaFlag1Bit`, `core/mpp/field_value.h` `kTaskFlag1FieldId`).
* `Flag2..Flag20`'s bit positions are **unmeasured**: `core/mpp/field_value.h` line
  54 says so, and `append_mpp12_flags()` implements the MPP12 contiguous layout
  (entry byte 37 bit `0x20` … byte 40 bit `0x01`) for the **MPP12** path only —
  this file is not MPP12.
* `PlanDocument` cannot invent a bit, and `core/mpp` is **not S6's to edit** this
  wave.  The gate therefore asserts **both halves**: the column exists in the
  file's table (`0x0b400051`, title `SUMMARY`), and
  `sheet.records().has_field(kSummaryFlagField) == false` with every row's cell
  empty.
* **To close it:** a `core/mpp` owner measures Flag10's bit on this file (the clean
  capture gives the ground-truth Yes/No per row) and either adds it to
  `Task::custom_fields` or exposes `flag(10)`.  Nothing in `app_qt` then needs to
  change: the RecordSet value would flow through `make_record_set()` and render as
  `Yes`/`No` — except that the column's kind would need to be `Bool` (below).

Follow-up shape, recorded so nobody re-derives it: once the bit is decoded, no
`app_qt` change is needed.  The column's `CellKind` is `Auto`, and a Bool value
formats itself as the sheet's `Yes`/`No` labels (`core/sheet/sheet.cpp`
`format_by_own_kind`), so the value would simply appear.

### `Resource Names` = `0x0b400031` — blank on these files
* `project_a.mpp`'s first table **does not contain the column at all** (10 columns,
  see the map) — Project's own capture of this file shows no Resource Names column
  either.
* Even if a table asked for it, the file has nothing to name: **all 67 live
  assignment rows store `0xFFFF0001` at +8** (mpxj's
  `ASSIGNMENT_NULL_RESOURCE_ID`) — the raw word is counted by the gate's oracle, not
  inferred from the mapped value.  The file has 22 resource rows but no
  task→resource link.
* The committed fixture has the same shape: 3 assignment rows, **all three** with
  the null word.
* The derivation itself is proven on a **constructed plan** in
  `case_computed_text_rules()` (`Alice, Bob` from two assignments, with the
  unassigned/unknown/nameless rows and another task's assignment all skipped).

## Gaps / not done

   **0 links** (measured), so the CI-visible gate proves the format and the wiring
   but not a non-empty value.  Closing it needs a fixture with a link (a
   `tests/data` change, not this lane's) or a writer-built link in a copy.
2. **`Flag10` decoding** belongs to `core/mpp` (owner: E7/wave 23).  This lane
   cannot add it; the gate already asserts the honest blank.
3. **Resource Names has no populated corpus column** — a file with a real
   `0x0b400031` column and real assignments is needed for an end-to-end proof.
4. **Lag unit labels** (`days` vs Project's `d`) are a shell-wide duration-label
   question, not this lane's; the Duration column reads `217 days` for `217 d`
   exactly as before.
5. A file with **no readable `214/CTable`** still falls back to
   `app::default_sheet_columns()`, which has no Pre/Suc/Resource Names column, so
   nothing changes for such a file (the Entry *captions* appear only for a new
   project, where there is no plan either).
6. The stock **Entry** presentation still has no Successors column (Project's stock
   Entry table doesn't either); a file's own table can add one, and now it renders.
