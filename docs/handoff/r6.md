## The gate — `app_qt/tests/ribbon_inventory_test.cpp`

New CTest entry `qt_ribbon_inventory` (registered in `app_qt/CMakeLists.txt`,
Carlito bundled like every other executable).  For **every** tab it asserts:

* `tab_titles()` is exactly the seven measured captions, in order, and
  `tab_count() == 7`;
* the model's `group_titles()` is exactly the pinned group list, in order, and
  each group's `group_button_labels()` + `group_button_action()` are exactly the
  pinned labels/actions in order;
* every button obeys decision 9: `isEnabled() == shell_implements(action)` and
  the disabled tooltip is the exact `"not implemented in this port"`;
* at 1920x1032: visible groups are a **prefix**, every visible group box,
  caption and button is wholly inside the ribbon and fits its whole text, and
  `overflow_button()->isVisible()` equals `groups_overflow()` equals
  `visible < total` for that tab;
* at 900x560 the same prefix/fit/chevron contract holds, and at least one tab
  overflows (Task 4/8, Resource 4/5, Project 3/6, View 2/7, Gantt Format 3/6);
* the contextual rule through the real view `QAction`s: open the fixture (Gantt
  view) → "Gantt Chart Format" tab visible; trigger Resource Sheet → tab hidden,
  still seven tabs in the model; trigger Task Sheet → visible again.

Note on the 1920 overflow criterion: our text-button model fits all seven tabs
at 1920 (Project's own 1911-wide captures fit all their groups too), so the gate
does **not** assert an artificial overflow.  It asserts the equivalence per tab
at both widths, and the 900 pass exercises the real overflow path.  "All visible
at 1920" is never required.

## Verified vs inferred

**Verified against the captures (pixels read locally):** every group caption and
its order on all seven tabs; every text button label and its order; the Task
tab's eight groups; the Resource 5 / View 7 / Report 3 / Project 6 / Help 1 /
Gantt Format 6 group counts; the View Data stack order (Highlight above Filter);
Window's Switch Windows; Report's single Export item (Visual Reports); Help's
three items; the Gantt Chart Style palette existence and position.

**Inferred (the capture cannot show the widget class through a static PNG):**
combo boxes are modelled as their label button (Timescale, Zoom); checkboxes as
text buttons (Timeline, Details, Critical Tasks, Slack, Late Tasks, Outline
Number, Project Summary Task, Summary Tasks); the Status Date label+date control
as the "Status Date" button; the Font family/size values as text buttons
(Arial/8); drop-down arrows are not modelled (the port is text-button only);
Gantt Chart Style's 16 swatches + preset drop-down are a palette with no text
commands, so its group is caption-only.

## What could not be verified / deliberate exclusions

1. **Keyboard tab order** of the stacked small buttons (2-D ribbon layout); the
   model uses the capture's visual reading order (left column, then the stacked
   column top-to-bottom).  The brief's starting order for Data had Filter before
   Highlight; the capture stacks Highlight above Filter, and the model follows
   the capture.
2. **Task tab formatting micro-controls**: the five % complete buttons, the
   indent/outdent arrows and the two Font colour pickers have no text-command
   model here.  Adding them would also break the Task tab's measured 1920 fit
   (`qt_empty_state` and the parity fixture).  They stay out, as before.
3. **Gantt Chart Style's 16 style names** are not visible in the capture (no
   tooltips/labels), so no invented labels were added; the group is a
   caption-only placeholder.
4. **Ribbon button commands with no `MenuAction`**: 102 ribbon buttons are
   `none` and disabled.  The implemented ones kept: Task's Paste/Cut/Copy,
   Insert Task, Information, Find, Clear; Resource's Add Resources
   (`insert_resource`, still disabled for the documented no-writer reason);
   View's Task Usage, Resource Usage, Resource Sheet, Filter.

  Help / Feedback / Show Training only; our previous Help tab had About and
  Keyboard Shortcuts, and the hidden classic menu bar is the only remaining
  home.  With the menu bar hidden, About is currently mouse-unreachable.  Wave
  23 should put About on the backstage Info/Account page (Project's own home for
  it) or the QAT.  This is an inventory-faithful loss, recorded rather than
  papered over.
* **Save as PDF / Export PDF left the Report ribbon.**  Project's Report tab has
  only Project / View Reports / Export (Visual Reports); the PDF commands remain
  on File ▸ Save As/Export in the menu model.
* **Zoom buttons left the View ribbon** (Timescale/Zoom/Entire Project/Selected
  Tasks are the measured group).  Zoom stays on the status-bar slider and the
  zoom actions' shortcuts.
* **Working-Day Shading (`toggle_shading`) left the contextual tab.**  The
  measured Show/Hide group is Outline Number / Project Summary Task / Summary
  Tasks; the command remains in the menu model with its shortcut.
* **Resource Sheet / Resource Usage and Task Sheet left their tabs' View
  groups.**  Project's Resource View group shows Team Planner (the other views
  live in its drop-down) and the View tab's Task Views has no "Task Sheet"
  item; our text-button model cannot render the drop-downs.  Both Resource views
  and the task sheet stay reachable from the four status-bar view buttons and
  the hidden menu, so this is a ribbon-only loss.  A future drop-down-capable
  ribbon button would restore Project's exact shape.
