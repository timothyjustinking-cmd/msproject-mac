Why the column order is nine columns and not eight: the reference's first 39 px

## 1. What matches (asserted by `qt_parity_geometry`)

`app_qt/tests/parity_test.cpp` runs the real window offscreen against
`tests/data/synthetic-base.mpp` and asserts:

* `verticalHeader()->defaultSectionSize() == 22`;
* `horizontalHeader()->height() == 42`;
* gutter column width 60, each of the nine Entry columns within **2 px** of
  39/57/147/81/81/81/105/105/123, content width 819;
* the live `QSplitter` fraction within 0.02 of 0.459, horizontal scrollbar
  visible under the sheet;
* Gantt: 42 px header, two 21 px tiers, day width 24 +/-0.5, a weekly label
  containing the year, single-letter day cells;
* colours exactly (255,255,255) / (212,212,212) / (247,247,247); selection
  `#dce9f5`, bar `#4a7ebb`;
* Calibri-11 typography with the pinned family list, the 7-tab ribbon
  (Task/Resource/Report/Project/View/Help + "Gantt Chart Format"), the timeline
  strip and the status-bar zoom slider wired to the zoom actions (slider to
  Day -> 20 px/day, back to Week -> 24 px/day).

**Geometry was validated against P1's harness without Qt.**  A 900x560 mock of
the same geometry is in `build/q2-scratch/mock.py` (git-ignored); running

```sh
python scripts/parity_report.py corpus/bench/msproject-gantt.png build/q2-scratch/mock.png
```

## 2. What does not match (honest list)

1. **The ribbon is structure only.**  Tabs, groups, captions and button order
   are there (text buttons, 105 px tall: 26 px tabs + 78 px groups); icons are
   simple glyphs, not the product's artwork (the brief puts pixel-exact ribbon
   icons out of scope).  At 900 px the rightmost groups are clipped, as a real
   ribbon is at a narrow width; the window stays 900x560.
2. **Task bar colour** is the shell palette, not a measured value: the current
   reference capture has no bars (docs/parity.md section 2.3).
3. **Column widths are data-driven now** -- `214/CTable` width characters x 6 px
   + 3 px padding reproduces the measured set exactly (24 chars -> 147 px,
   13 -> 81, 17 -> 105, and the 20-character stub -> 123).  `PlanDocument` reads
   the bytes through `core/viewstate` and `MainWindow::configure_sheet` converts
   them; `qt_parity_geometry` asserts the readback (Task Name = 24 chars) and the
   conversion.  The one caveat: if the `core_mppwrite`/`core_viewstate` include
   paths do not reach `app_qt` in CI (see section 5), the readback falls back to
   the stock default character widths -- which produce the same 819 px set, so
   the pixels do not change.
4. **Row-number gutter scrolls with the columns** (it is column 0) rather than
   staying frozen.  Freezing it needs a second viewport overlay; out of scope
   this wave and not measured by the harness.
5. **No bars are drawn in the reference**, so bar/milestone/summary shapes are
   unchanged from Q1 and unverified against the product.
6. **Not compiled.**  Everything below is written conservatively (Qt 6.2,
   Widgets only, no `Q_OBJECT`/AUTOMOC, no new third-party code) but has not
   been through a compiler.  The three likeliest CI errors are listed in
   section 5.

## 5. Three likeliest CI errors (not compiled here)

1. **`QFontDatabase::families()` / `QStringList` in `main_window.cpp`.**
   `families()` is a static in Qt 6, but the file relies on `<QFontDatabase>`
   and `<QStringList>` being included (both are, explicitly).  If the CI Qt is
   built without FontDatabase support (unlikely on the distro package) the
   family list resolves to the platform default instead of failing.
2. **`QHeaderView::paintSection` / `QStyledItemDelegate` overrides in
   `sheet_views.cpp`.**  The signatures are Qt 6's; a Qt 6.2-vs-6.5 drift in
   `QStyleOptionViewItem` would show here first.  The header also calls
   `setFixedHeight` inside the constructor; harmless.
3. **The `214/CTable` readback in `plan_document.cpp`** includes
   `cfb_writer.h` and `viewstate.h`, which resolve through `app_layout`'s PUBLIC
   links to `core_mppwrite`/`core_viewstate`.  If the coordinator's configure
   builds `app_qt` standalone in a way that does not propagate those interface
   include directories, this is the first (only) failure; the fix is one
   `target_link_libraries(qt_shell PUBLIC core_mppwrite core_viewstate)` line,
   or deleting `read_table_column_widths()` and the two call sites (the shell
   does not need it for any measured number).

## 6. Traps for the successor

1. **The header band's rules are load-bearing for P1's harness.**  The caption
   band must have a top rule (the timeline strip's bottom border) and a bottom
   rule on the *first row's boundary* (drawn by the row-0 cells in the
   delegate).  Drawing the header's own top/bottom rule moves the measured
   header height by 1-2 px; the mock proved 43 px with the current split.
2. **The Gantt's first visible day must be Sunday or Monday.**  The harness
   infers the chart's left edge from the first weekend band: a clipped first
   band (Sunday start) or a band exactly five days in (Monday start) recovers
   the edge; any other weekday shifts it by up to five days and the splitter
   measure fails.  `PlanDocument::build_gantt` sets `week_start = 0` and the
   timescale snaps to the week start.
3. **The character-width rule is 6 px + 3, not 7 px.**  The committed
   `synthetic-base.mpp` stores 6/9/24/13/13/13/17/17 characters; the reference
   measures 39/57/147/81/81/81/105/105 px.  Only `chars*6+3` reproduces that set;
   `chars*7` (the value `core::sheet::SheetMetrics::char_width` defaults to)
   gives 42/63/168/91... and is wrong for this table.  The shell uses its own
   constant (entry_columns.h) rather than SheetMetrics for exactly this reason.
4. **The splitter handle paint colour matters.**  A light grey fill (239/247)
   in the shaded-pixel range would be detected as a Gantt weekend band and
   corrupt the day-width measurement; the handle is painted white with grey
   edges for that reason.
5. **`kSplitFraction` is the *centre* of the 6 px handle**, so the sheet pane is
   `round(0.459*width) - 3`.  The harness then measures the handle's two edges
   and the chart divider and lands on 0.4589.
