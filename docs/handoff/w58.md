## 3. API

```cpp
struct WriteError { std::string message; };

struct EncodedParts {
    std::vector<std::uint8_t> fixed_data, fixed_meta, var_meta, var2_data;
    PartSet parts() const;                 // non-owning view, decoder-shaped
};

bool encode_view_state(const ViewState&, EncodedParts&, WriteError* = nullptr);

bool set_table_date_format(ViewState&, std::size_t table_index,
                           std::uint8_t date_format, WriteError* = nullptr);

bool set_table_column(ViewState&, std::size_t table_index,
                      std::size_t column_index, std::uint32_t field_id,
                      std::string_view title, WriteError* = nullptr);
```

`PartSet` is a set of spans, so it cannot own encoder output; `EncodedParts` is
the owning result and `parts()` returns the `PartSet` the decoder takes. The
task's `encode_view_state(const ViewState&, PartSet&)` sketch is therefore
realised as `EncodedParts` instead of an output `PartSet`.

## 4. What encode does, byte-wise

`encode_view_state` re-serialises the four parts from the parsed structure;
it is not a blind copy of the four raw buffers:

- **FixedData**: emitted verbatim. Its 16-byte identity/GUID-like value churns
  on every Project save and cannot be generated compatibly, so the writer
  preserves it (and all other opaque FixedData bytes) exactly.
- **FixedMeta**: 16-byte header is rewritten (`magic 0xfadfadba`, parsed
  `flags`, `declared_count = entries.size()`, `fixed_data_size = fixed_data.size()`),
  then each entry's `state`, `var_count`, `fixed_offset` and opaque tail (+8)
  are written. `entry_size` comes from the parse; an entry whose tail length
  disagrees is refused rather than padded or truncated.
- **Var2Data**: every block is re-framed in stream order (`u32 length` +
  payload), and the new offsets of the length words are recorded. The payload
  bytes come from the parsed `var2_data`, so a mutator that patched a payload
  byte is included.
- **VarMeta**: the 24-byte header is rewritten with `declared_count =
  entries.size()`, `var2_size = Var2Data.size()`, and every entry's offset is
  the **recomputed** block offset. The three reserved header words (+4, +12,
  +16) and any trailing bytes after the declared entries are preserved from the
  parsed stream so a no-op encode stays byte-identical. Entries are matched to
  blocks by `(uid, key)`, preferring the block at the entry's original offset;
  two blocks can share a `(uid, key)`, and then the old offset disambiguates.
  An entry with no matching block is refused (its offset cannot be recomputed).

Encode refuses a state that did not come from a successful
`parse_view_state()` (`ViewState::parsed == false`), and leaves `out` empty on
any failure.

## 5. The two mutations

### 5.1 `set_table_date_format`

Writes `state.var2_data[block_offset + 4 + 7]` and updates
`TableDef::date_format`. `block_offset` is the position of the block's length
word, so payload +7 is stream offset `block_offset + 11`. Measured fixture: the
single block starts at 0, so the changed byte is Var2Data stream byte **11**.

Evidence: wave-10 prefs `col -> date` differs in exactly that byte under `214/`
(`0xff -> 0x05`; docs/handoff/w56.md section 8.2). The test additionally starts
from the committed `col` blob, calls the mutator with `0x05`, encodes, and
requires the result to equal the committed `date` blob byte-for-byte. Only
`0xff` (default) and `0x05` are measured; the function passes any `u8` through
and makes no claim about the other values.

### 5.2 `set_table_column`

At `column_index`, writes the u32 field id at record +0 and the UTF-16 title at
record +13; the 9 opaque bytes at +4 are **preserved**. The title area (102
bytes = 51 code units) is zero-filled and then the title characters are
written, matching Project: the w14 `tablecol2-I` (Number1) vs `-J` (Text1)
pair differs only inside one 115-byte record and the shorter title's tail is
zeros (diff bytes 127, 140, 142, 144, 146, 148, 150, 152 -- field-id low byte
and the title area). Absolute record position in a Var2Data stream is
`block_offset + 4 + kTableBlockHeaderSize + index * kColumnRecordSize`
(that is `4 + 12 + index*115` for the single-block fixture), not
`12 + index*115`; the 4-byte length word is easy to forget (trap hit in this
stream's first test run).

A title of exactly 51 code units is accepted (there is then no NUL in the
record; the decoder reads it by capacity). 52 is refused. Only printable ASCII
is accepted because `utf16_ascii` (the decoder) reads printable ASCII titles;
a non-ASCII title would not round-trip.

**Replacement only.** The oracle's `TableEdit(..., ColumnPosition=0)` replaced
index 1 of the 9-column Entry table, and `ColumnPosition` 8/9 is rejected by
Project. Appending would need to grow the block length, `last_column_index`,
and possibly FixedMeta/VarMeta; none of that is measured, so no append API is
offered.

## 7. Proved / inferred

**Proved by this stream's tests:**

- encode of an unmutated parsed collection is byte-identical in all four parts;
- `col` + `set_table_date_format(0x05)` == the committed `date` blob;
- a date-format edit changes exactly stream byte 11 in the one-block fixture
  and no other part;
- a column replacement changes only the targeted 115-byte record, writes the
  field id and title, preserves the 9 opaque bytes and zero-fills the tail;
- every refusal returns false with a message and leaves the parts unchanged;
- encode refuses an unparsed `ViewState`;
- 51-code-unit title accepted, 52 refused;
- the generic framing round-trips on empty collections and on a two-table
  CTable, and on 72 real extracted collections across all 8 classes.

**Proved by the oracle (w14-oracle.md section 1), reused here:**

- a 115-byte column record, field id at +0, 9 opaque bytes, UTF-16 title at
  +13, 51-unit capacity;
- `ColumnPosition=0` replaces the record at index 1 and does not change the
  1047-byte block; `ColumnPosition` 8/9 is rejected;
- a new table appends one 230-byte FixedData row, one 10-byte FixedMeta entry,
  one VarMeta entry keyed `0x20400006` and one Var2Data block.

**Inferred / assumed (not independently proved here):**

- preserving the 9 opaque column bytes on replacement. The oracle's Number1
  and Text1 records had identical 9 bytes (`0c1008000801000000`), so
  preservation is consistent with the measurement, but no oracle case changed
  colour/width/align while holding the field constant. The alternative
  (Project regenerates the header per field) cannot be excluded from that pair.
- zero-filling the title tail matches the I/J pair; no case replaced a title
  with a longer one (the tail behaviour for growth is not measured).
- `0xff` meaning "application default" and the meaning of the other date-format
  codes.
- Keep-the-reserved-header-words/trailing-bytes policy in `VarMeta` is a
  byte-preservation choice; the measured fixtures have zero reserved words and
  no trailing bytes.

**Measured only indirectly:** the writer never writes FixedData, so the
identity/GUID rule (Project regenerates it every save) is respected by
preservation, not by generation. A saved `.mpp` containing writer output has
not been round-tripped through Project by this stream (the oracle is
coordinator-only and no `.mpp`-writing path is wired here).

## 8. Not written / open items

1. **Append a column.** Unmeasured. Needs a single-variable oracle case where
   Project actually grows the column count (the accepted `ColumnPosition`
   range was 0..7 and meant "replace index 1", so a different API route or a
   table created with more columns is needed). Until then the block's `+4`
   (`last_column_index`), the block length and any FixedMeta/VarMeta growth are
   guesswork, and the API deliberately refuses to grow.
2. **CV_iew item encoding.** The main `0x20400006` view blocks (42572/42692/
   8272 B) still have a Props-like header but a non-Props item encoding. No
   view edit is written. A successor needs one oracle view-property change
   (e.g. zoom or column width in a view) and a diff against the control save.
3. **CEdl / `214/Props` semantics.** CEdl's block is a Props document (last
   view/table names, a host path) and `214/Props` is an ordinary Props stream;
   the writer rebuilds their framing but does not interpret or edit their
   records. What a view/table selection should persist there is unmeasured.
4. **Column-record opaque 9 bytes.** Width/align/title-format semantics remain
   unidentified. The writer preserves them; a UI that changes width cannot yet
   persist it.
5. **The other classes.** CFilter/CGrouping/CMap/CDrawing/CReport payloads are
   opaque; only their generic framing round-trips.

Next three concrete actions for a successor:

1. Wire `encode_view_state` into the app's save path behind an explicit
   "view state only" flag, and add an integration test that writes the four
   parts back into a copied `.mpp` (CFB writer) and has the coordinator open it
   in Project once.
2. Ask the coordinator for one oracle case that grows a CTable column list so
   the append layout is measured; add `append_table_column` only then.
3. Ask the coordinator for one CV_iew single-variable save (view zoom/column
   width) and diff the `0x20400006` block; that is the next view-state write.

## 9. Traps

- **Two offsets per block.** `VarBlock::offset` and `TableDef::block_offset`
  point at the `u32 length` word; block *payload* starts 4 bytes later. Payload
  +7 is stream `block_offset + 11`; column record `i` is stream
  `block_offset + 4 + 12 + i*115`. The first version of the column test used
  `12 + 115` and read the wrong bytes.
- **Do not diff `base` and `date` directly to reproduce the date save.** `base`
  has table flags 6 and `col`/`date` have flags 2 (the wave-10 flag churn). The
  one-byte equivalence only holds from `col` (flags 2, date 0xff).
- **VarMeta entry order is not block order** (CV_iew groups by uid). Recompute
  offsets by matching `(uid, key)` to the block walk; do not assume entry `i`
  names block `i`.
- **Identity/GUID bytes churn per save.** Never synthesise them; the writer
  copies FixedData and every 16-byte tail verbatim.
- **MSVC C4244 in `std::fill`**: `std::fill(vec<uint8_t>::iterator, ..., 0)`
  promotes to `int` and `/W4 /WX` rejects it. Use `std::uint8_t{0}`.
- **`ctest` is not on the bare PATH here**: invoke it after `vcvars64.bat`.
- The committed blobs are raw Var2Data only; the other three parts are built
  from the framing constants in the test, so keep `kFixedMetaHeaderSize`,
  `kVarMetaHeaderSize`, `kTableBlockHeaderSize`, `kColumnRecordSize` and the
  test generator in sync.
