## Layout 1 — Task Cost1..Cost10 (measured: `w14-cost`, `w14-cost2`)

`Task.Cost1` = PjTask `0x0b40006a`; Cost1..Cost3 = `0x0b40006a..6c`,
Cost4..Cost10 = `0x0b400102..108` (`core/mpp/field_value.h`).

| store | measured change |
|---|---|
| `114/TBkndTask/VarMeta` | one new entry `(uid, offset, <field id>)` — **the key IS the field id**, inserted in ascending-key order inside the uid group (w14-cost: entry 10, after Name) |
| `114/TBkndTask/Var2Data` | block appended at the current end: `u32 len 8` + **f64 of the value in hundredths** |
| `114/TBkndTask/FixedMeta` | the row entry's `+2` u16 +1 and the presence bit set |
| `114/TBkndTask/Props` | one 88-byte record keyed by the field id |
| `114/TBkndAssn/Props` | one 88-byte record keyed by the assignment property id (`0x0f40401e` for Cost1) |

Value encoding, measured twice: `123.45 -> 12345.0` (`w14-cost`), `1.23 -> 123.0`
and `0.07 -> 7.0` (`w14-cost2`, coordinator). The conversion is
`llround(cost * 100.0)` stored as an f64, and a value whose hundredths do not
round-trip (`123.456`) is **refused**, not silently rounded. `cost` is the
currency value the caller supplies; read-back is `stored_f64 / 100.0`.

Presence bits: the 47-byte FixedMeta entry tail is a bitmap starting at entry
byte **+21**, indexed by the field's decompiled *class slot*
(`analysis/field_definitive_map.tsv`, storage class 5):
`byte = +21 + slot/8`, `mask = 1 << (slot%8)`.

| field | class slot | tail bit | status |
|---|---|---|---|
| Text1 | 5 | +21 0x20 | measured |
| Flag1 | 25 | +24 0x02 | measured |
| Number1 | 35 | +25 0x08 | measured |
| Number2 | 36 | +25 0x10 | measured |
| Duration1 | 40 | +26 0x01 (+ marker 0x0b4000b7 → slot 53, +27 0x20) | measured |
| Cost1 | 43 | +26 0x08 | **measured** |
| Cost2 | 44 | +26 0x10 | inferred |
| Cost3 | 45 | +26 0x20 | inferred |
| Cost4 | 63 | +28 0x80 | inferred |
| Cost5 | 64 | +29 0x01 | inferred |
| Cost6 | 65 | +29 0x02 | inferred |
| Cost7 | 66 | +29 0x04 | inferred |
| Cost8 | 67 | +29 0x08 | inferred |
| Cost9 | 68 | +29 0x10 | inferred |
| Cost10 | 69 | +29 0x20 | inferred |
| Date1 | 70 | +29 0x40 | measured |

The rule reproduces all seven measured bits; Cost2..Cost10's bits are the
inference. **One oracle fixture with Cost4** (the first field in the +28 byte)
would confirm the family.

Exact Cost1 Props records (measured bytes, copied):

```
Task/Props (86 + 88):  6a 00 40 0b 05 00 00 00 1e 40 40 0f 00 00 00 00
                       00 00 00 00 b7 39 00 00 be 8b eb 4c 82 c4 fa 8c
                       0b 40 00 6a  then 52 zero bytes
Assn/Props (88 + 88):  1e 40 40 0f 05 00 00 00 6a 00 40 0b 00 00 00 00

```

Cost2..Cost10 use the same record with their own id/key (`0x0f40401e+n-1`);
`+4 = 5`, `+12 = 0`, `+16 = 0`, `+20 = 14775`, `+24/+28` are the two opaque
stamps, the id/key repeated big-endian at `+32`. The two 32-bit stamps
(`0x4ceb8bbe`, `0x8cfac482`) are **measured, not explained** — copy them.

## Layout 2 — assignment Number1..20 / Text1..30 (measured: `w14-assignfield`)

The values live in `114/TBkndAssn`, **not** in the Task table. The VarMeta key is
the assignment property id, not the PjField id:

| field | VarMeta key | evidence |
|---|---|---|
| Assignment.Number1 (PjField `0x0f40006c`) | `0x0f40403c` | w14-assignfield (oracle) |
| Assignment.Number2 | `0x0f40403d` | w10-fieldvalues, w11 etc. |
| Assignment.Number15 | `0x0f40404a` | project_b/project_a Assn Props |
| Assignment.Text1 (PjField `0x0f400058`) | `0x0f404064` | w14-assignfield (oracle) |
| Assignment.Text2 | `0x0f404065` | project_b/project_a |
| Assignment.Text4 | `0x0f404067` | project_b/project_a |
| Assignment.Text6 | `0x0f404069` | project_b/project_a |
| Assignment.Text10 | `0x0f40406d` | project_b/project_a |
| Assignment.Text11 | `0x0f40406e` | project_b/project_a |
| Assignment.Text20 | `0x0f404077` | project_b/project_a |

The key table is `key(NumberN) = 0x0f40403c + (N-1)`,
`key(TextN) = 0x0f404064 + (N-1)`. The bases and the stride-1 continuation are
measured from Project's own files' assignment-side Props records (each record
carries the key at +0 and the PjTask field id at +8): `w10-fieldvalues.mpp`,
`w14-assignfield.mpp`, `project_b.mpp`, `project_a.mpp` pin
Number1/2/15 and Text1/2/4/6/10/11/20 exactly. Number3..20 and Text2..30 use
the same stride (the only formula consistent with every measured pair).

What one write changes:

| store | measured change |
|---|---|
| `114/TBkndAssn/VarMeta` | one 12-byte entry `(assignment uid, Var2Data offset, property key)` **appended after the uid's existing entries** — assignments are NOT key-sorted (the measured group runs `0x0f400010`, `0x0f400020`, …, `0x0f40029b`, then the custom entries). Header `+8` count and `+0x14` Var2Data size updated. |
| `114/TBkndAssn/Var2Data` | block appended at the end: Number = `u32 len 8` + **plain f64** (7.5, not 750); Text = `u32 len` + UTF-16LE + NUL (`assign-text` = 24-byte payload). |
| `114/TBkndAssn/FixedMeta` | ONLY the row entry's `+2` u16 (its exact VarMeta entry count, 9 -> 11). **No tail presence bit changes for an assignment** (measured). |
| `114/TBkndTask/Props` | one 88-byte record keyed by the PjTask field id, with the assignment key at `+8`. |
| `114/TBkndAssn/Props` | one 88-byte record keyed by the assignment key, with the PjTask field id at `+8`. |

Record shapes (both verified byte-identical to Project's in the test):
`{id|key, typeA, key|id, typeB, 0, 0, 14775, 0x4ceb8bbe, 0x8cfac482,
id|key big-endian at +32, zeros}` with `typeA/typeB = 8/7` for Text and `5/5`
for Number. The stamps are measured opaque words.

`114/TBkndAssn/FixedData` (110-byte rows), `Fixed2Data` (48-byte records) and
`Fixed2Meta` (16 + 53·rows) are never touched.

## Exact new API (`core/mppwrite/field_values.h`)

```cpp
struct FieldValue { … double cost = 0.0; … };

// Task side: Cost1..Cost10 go through the existing call.
FieldWriteResult save_field_values(CfbDocument&, std::vector<FieldEdit> const&,
                                   std::string const& path,
                                   std::string_view table = "114/TBkndTask");
ClearedField clear_field_value(…);            // now also accepts Cost1..Cost10

// Assignment side (W60):
std::uint32_t assignment_property_id(FieldKind kind, unsigned index); // 0 = not measured

struct AssignmentFieldEdit { std::uint32_t assignment_uid = 0; FieldValue value; };
struct AssignmentFieldWrite { std::uint32_t assignment_uid = 0; FieldValue value; };
struct AssignmentFieldWriteResult {
    std::size_t fields_written = 0;
    std::vector<AssignmentFieldWrite> fields;
    std::vector<std::string> warnings;
};
AssignmentFieldWriteResult save_assignment_field_values(
    CfbDocument& doc, std::vector<AssignmentFieldEdit> const& edits,
    std::string const& path);

FieldValue read_assignment_field_value(CfbDocument const&, std::uint32_t assignment_uid,
                                       std::uint32_t field_id);

struct FieldStores {
    bool var_meta, var2_block, presence, registered, flag_field;
    bool complete() const;    // the W48/W60 “Project will display it” rule
};
FieldStores field_stores(CfbDocument const&, std::uint32_t uid,
                         std::uint32_t field_id,
                         std::string_view table = "114/TBkndTask");
FieldStores assignment_field_stores(CfbDocument const&, std::uint32_t assignment_uid,
                                    std::uint32_t field_id);
```

`save_assignment_field_values` is all-or-nothing like the Task writer: validate
everything (assignment uid, row, live task, field family, value, duplicates,
damaged table), apply on a copy, save, re-open from disk, and require
`FixedData/Fixed2Data/Fixed2Meta` byte-identical, only the target entry's `+2`
changed in FixedMeta, the VarMeta multiset = every original entry (repointed
where edited) + the appended entries in edit order, Var2Data byte-identical to
the appended build, both Props registries byte-identical for old records and
exact for new ones, and every value re-read through the same decoder. A refusal
leaves `doc` and the output path untouched.

## Remaining refusals (deliberate, clear errors)

- Task `Flag2..Flag20` (bit positions unmeasured) and every unknown id.
- Task Text2..30 / Number3..20 (no measured `Props` record; the record encodes
  the field's format, so a template from another family would be a guess).
  Cost is no longer refused.
- Assignments: everything except Number1..20 / Text1..30 — assignment Cost,
  Flag, Date and Duration are unmeasured there.
- A Cost value that is not finite or not representable in hundredths.
- Damaged tables: a Task table whose size identity is broken; an assignment
  table whose six stream geometries / header count-size words / FixedMeta entry
  coverage / VarMeta declared count disagree (the same strict policy W54's
  add/delete uses — PROJECT_A's 69-row/68-entry assignment table is therefore refused
  for an assignment field write).
- An assignment whose row is a tombstone or a placeholder (task uid 0), or whose
  task uid has no live Task row.
- No field delete and no assignment clear API (not measured; the Task clear is
  the W52 empty-value shape and now covers Cost).

## Traps hit

- **The assignment VarMeta key is not the field id** (`0x0f40403c` for
  `Assignment.Number1`); writing the PjField id would be silently ignored.
- **Project appends assignment custom entries; it does not key-sort them**
  (measured group order). Task entries are inserted key-ascending; the two
  behaviours are deliberately different implementations.
- **The assignment table's FixedMeta has NO tail presence bit** for a custom
  value; only `+2` changes. The Task side needs the bitmap.
- **Cost is hundredths as an f64 and the multiply must be decimal-safe**:
  `0.07 * 100.0` is `7.000000000000001`, Project stores `7.0`.
- The Cost FixedMeta bit is the class-slot bitmap, not a hand-assigned per-field
  constant; the decompiled class slots are what made all ten Cost ids writable
  without guessing.
- `save_field_values`'s generic `save_and_verify` calls `check_table`, which is
  Task-specific (202-byte rows, 47-byte entries, rows+3); the assignment writer
  therefore uses `save_assignment_and_verify` + its own W54 geometry validation.
- The `w14-cost` / `w14-cost2` / `w14-assignfield` fixture pairs carry a
  project-title block difference in `TBkndTask/Var2Data` (FileSaveAs churn).
  Compare per stream: our write reproduces `VarMeta`/`FixedMeta`/`Props` and the
  **Assn** Var2Data byte-for-byte, but the Task Var2Data prefix is the control's
  title, not the target's.
- MSVC `/W4` C4456 caught a shadowed `base` local in the new test; `/WX` makes
  it fatal. Clang would also flag unused lambda captures.
