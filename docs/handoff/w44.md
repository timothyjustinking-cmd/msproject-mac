## Nesting guard (wave-13 fuzz follow-up, then the ASan follow-up)

W57 measured that `parse()` on **256 nested `IIf`** or **384 nested
parentheses** died with `0xC00000FD` (MSVC Release); 128 was fine, so a bound of
160 was added. Under **AddressSanitizer** the instrumented frames are much
larger: in `build\vs-w57-asan` (Debug, `/fsanitize=address`) 64 and 72-deep
parsed but **80/88/96/128/160 overflowed before the 160 guard could fire**. The
bound is therefore **64**: below the ASan-measured good depth, safe on every
build and thread, and far above real formulas (fewer than ten levels deep).

- `core::formula::kMaxFormulaDepth = 64` (`expr.h`) is the one shared bound:
  nesting up to and including 64 is accepted; 65 is the first refused level.
- Parser recursion: RAII `DepthGuard` in `parse_or` (parentheses, call arguments,
  binary operands) and in `parse_unary` (unary chains). Errors are positioned,
  e.g. `offset 65: formula nesting exceeds 64 levels`.
- AST tree depth (`Expr::depth`, in edges): `finish_node()` refuses a node whose
  tree height exceeds 64. This is NOT redundant: a long FLAT chain
  (`1 And 1 And ...`) parses iteratively but builds a left-deep tree whose
  **recursive destructor** overflowed under ASan. Parsed output is always
  shallow enough to destroy and evaluate; a >64-operator flat chain is refused
  at parse time.
- Evaluator: `check_structure()` checks depth before recursing, so a hand-built
  deep AST is refused with `ok=false`; no exceptions anywhere.

## Measured vs inferred

Measured (oracle `docs/analysis/oracle/w10-oracle.md` §2, fixture
`corpus/probe/w10-fieldvalues.mpp`):
- custom-field ids: Text1 `0x0b400033`, Flag1 `0x0b400048`, Number1 `0x0b400057`,
  Duration1 `0x0b400067`, Cost1 `0x0b40006a`, Date1 `0x0b400109`; Number2
  `0x0b400058`;
- encodings: Text = UTF-16LE NUL-terminated; Number = LE f64; Duration = u32
  file ticks (4800/day, COM minutes ×10); Date = `(day<<16)|(sec/6)`, day 0 =
  1983-12-31;
- formula tokens: `[Duration]` = `[MSPJ188744967]` (Task.DurationText,
  `0x0b400507`), `[% Complete]` = `[MSPJ188743712]` (PercentComplete,
  `0x0b400020`);
- the registry counts/name/id triples (generated descriptor table).

Inferred (no oracle run evaluates a formula; Project does not compute custom
fields into headless `GetField`):
- all operator semantics, precedence, `IIf` laziness, null/truth/coercion rules;
- date arithmetic (calendar-free: whole 4800-tick days + 6 s/tick remainder;
  `date - date` is its exact inverse) — Project would consult the task calendar;
- `DurationText` falling back to Task.Duration;
- the function set and `ProjDurValue`/`ProjDurConv` unit meanings;
- `&` rendering through `core/sheet`'s display formatting.

Our choice, explicitly unmeasured: **Flag** storage (u32 LE 0/1) and **Cost**
storage (f64). Both are marked `StorageConfidence::Unmeasured` in
`fields.h` and asserted as such; the next oracle is a two-file diff with Flag1
set once and Cost1 set once.

## Traps

- `kMaxFormulaDepth` is 64 and must not be raised without re-measuring under
  ASan (72 parsed, 80 overflowed there; Release tolerates more, which is the
  trap). Tests require 64 nested parens/IIf to parse, so 64 is also the floor.
- Do not remove `finish_node`'s AST tree-depth guard: the `parse_or`/
  `parse_unary` guards bound parser recursion, but a long flat chain builds a
  deep left-nested tree whose **destructor** overflows the stack (ASan-measured).
- Keep the `parse_unary` guard as well as the `parse_or` one.
- Duration ticks are working-time (4800 = 8 h); date math must not use
  `kTicksPerDay` as a day or 08:00 becomes a day (this cost one test cycle).
- Inside `ComputedColumns`, an unqualified `evaluate(...)` resolves to the
  member overload; qualify `core::formula::evaluate`.
- `core::view::Value` has no `operator==`; compare `kind` plus the member.
- Ids beyond the six anchors must come from `find_custom_field`; never hard-code.
- Dropbox mtime churn: re-read the exact region immediately before every edit.
- Test binary paths: Release
  `build\vs-w44b\core\formula\Release\formula_tests.exe`, ASan
  `build\vs-w44-asan\core\formula\Debug\formula_tests.exe` (run through vcvars so
  the ASan runtime DLL resolves), fuzz
  `build\vs-w44b\tests\fuzz\Release\fuzz_parsers.exe`; ctest filter
  `-R "formula"`.
