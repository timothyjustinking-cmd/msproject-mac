## 1. Result

`app::save_structural_edits` now has the seam the gap asked for:

```cpp
using DocumentEditHook =
    std::function<DocumentEditOutcome(mppwrite::CfbDocument& document,
                                      const ViewStateEdits& view,
                                      const CustomFormulaEdit& formula)>;

struct StructuralDocumentEdits {         // the request, including the hook
    ViewStateEdits view;
    CustomFormulaEdit formula;
    DocumentEditHook hook;               // app::apply_document_edits fits exactly
    bool any() const noexcept;
};

StructuralSaveResult save_structural_edits(..., bool allow_source_overwrite,
                                           const StructuralDocumentEdits& document_edits = {});
```

The hook is invoked **once, after the field-value writers (`save_field_values` /
`clear_field_value`) and before the one final write**, with the `CfbDocument`
those writers already own plus the pending `ViewStateEdits` /
`CustomFormulaEdit`. It mutates the document in memory only (the cascade owns
every file write) and returns `DocumentEditOutcome`: `ok == false` fails the
whole save before the target is written; a refused **view-state** request stays a
warning, forwarded into `StructuralSaveResult::warnings`, like everywhere else.

`app::apply_document_edits` has exactly the hook signature, so the shell passes
it directly. `Document::save_structural()` (document.cpp) is the one-call form:

```cpp
app::StructuralSaveResult outcome =
    plan.document->save_structural(plan.edits, edits, target, plan.owns_path);
```

**No hook, no change.** With an empty request the cascade runs the pre-wave-17
sequence — same writer calls, same write routing, same bytes. Proved on the
fixture, not asserted: see §5.

## 3. The pipeline, exactly (do not reorder)

```
link deletes -> link adds -> task deletes -> task inserts
             -> custom-field VALUES (save_field_values / clear_field_value)
             -> 5b: document-edit hook  [formula (114/Props) -> view state (214/CTable)]
             -> ONE final write
             -> reload
```

The final write, with a hook supplied:

| situation | the final write | why |
|---|---|---|
| a start pin is writable | `mppwrite::save_date_edits` (as today) | it was already the last writer; the hook runs before it, on the same `CfbDocument`, so its file contains the hook's streams. |
| no start pin | one explicit `mppwrite::CfbDocument::save` (new `6b`) | otherwise the last field/link/task writer would have written the target *before* the hook ran. An explicit save is the only way to keep "hook first, then the one target write". The container is re-read and required to re-emit byte-identically, and `check_table` is reported as a warning (the writers that normally prove the file did not run last). |

The write-op count (`write_ops`) is still computed before anything is written, so
**every earlier writer writes the intermediate `.w51-structural-tmp` file and only
the last op writes the target** — with or without a hook. A hook refusal
therefore leaves no target behind and removes the intermediate.

`Document::save_structural()` passes a null hook when nothing is pending, so a
structural save with no view-state/formula request takes the old path exactly.

## 8. Proved here vs not

**Proved on this box (test + re-runnable command):**

- the cascade with no hook is byte-identical to the pre-change binary's output
  and to the documented writer sequence (§5);
- one save carries an insert, a custom-field **value**, a `214/CTable` edit and a
  `114/Props` change, and the reopened file has all four;
- the `0x02401392` decision sees a value written **in the same save** (and does
  not see one when there is none — the control run);
- both final-write branches: `save_date_edits` last (start pin) and the explicit
  `CfbDocument::save` last (no start pin);
- a hook refusal fails the save cleanly with the target untouched, and pending
  edits without a hook are refused rather than dropped;
- `Document::save_structural` is the same path as the free-function call;
- A1's second write, if left in place, is a no-op (byte-identical).

**Inferred / not proved here:**

- that **MS Project accepts** a file written by the one-write path. The streams
  are the same measured edits as w64's and the date pin is W37's, but no `.mpp`
  containing this output has been opened in Project. COM is coordinator-only
  (docs/coordination.md rev. 3).
- that `main.mm` compiles against `Document::save_structural` and the deleted
  fallback: `main.mm` is ObjC++/AppKit and is not built on this box. The API
  shapes in §4 match `app/document.h` / `app/edit_model.h` exactly.

**Ordering cases still unreachable / uncovered:**

1. **`clear_field_value` then a formula clear, in one save.** The hook would run
   after the clears, and `custom_field_value_remains()` deliberately answers "yes"
   for a cleared field whose VarMeta entry survives (W52), so the flag stays 1.
   Nothing here changes that, but no test exercises the *cleared-value* ordering
   (only the written-value one). If a future stream wants the flag down after
   "clear every value, then clear every formula", that needs a value predicate
   that understands the cleared shape — not a reordering.
2. **A formula *set* whose ordering matters.** W59's setter always writes flag 1,
   so a set cannot distinguish "hook before" from "hook after" the value writers;
   only the clear can, and that is the case covered.
3. **MS Project acceptance** and the **shell run** (above).

## 9. Traps hit (do not relearn)

- **`app/edit_model.cpp` is CRLF; the other app files are LF.** A patch script
  that assumes one ending silently matches nothing. The helper used here
  (`build\b1-scratch\b1patch.py`) re-encodes anchors to each file's own ending and
  asserts every anchor appears exactly once before writing anything.
- **Dropbox mtime churn broke `edit`/`write` again** ("file changed since it was
  read", including on files created minutes earlier). Workaround as above: an
  all-or-nothing Python patcher under `build\b1-scratch\`.
- **A concurrent stream's `core/viewstate/viewstate.cpp` broke the `/WX` build**
  (C4458 `klass` hides class member, at 10:11; not this lane). The gate could not
  run until it was fixed; a `-DCORE_WARNINGS_AS_ERRORS=OFF` shadow tree
  (`build\b1-app-nowx`) was used to validate the tests meanwhile. Retry before
  suspecting your own change.
- **The fixture was momentarily a stale Dropbox copy** (`EC5C0443…` here, and
  `092C51BD…` per memory/fuzz.md F3) before the coordinator restored
  `55C109F2…6069`. Every hash in this file was **re-measured after the restore**;
  an earlier measurement (`F31A639F…4058`) is void — it was the stale file. Run
  `python scripts/check_fixtures.py` before quoting any hash.
- **Do not run the full `ctest`** in this wave: concurrent runs truncated
