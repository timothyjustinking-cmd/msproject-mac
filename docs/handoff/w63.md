## Why this stream exists, and what it replaced

The only macOS proof in this project is GitHub Actions and nobody here has a Mac, so the
"manual Mac smoke test" the earlier waves kept deferring could not be run by anyone. This
stream replaces it with an automated one:

* **portable half** — `app/smoke.{h,cpp}` (plain C++, no AppKit) drives the real portable
  models through the real sequences and records a named check for each decision. It is
  unit-tested on this Windows box as **`app_smoke`** (`app/smoke_tests.cpp`, 98 checks).
* **AppKit half** — `app/main.mm` runs that report, then the AppKit paths a human would
  use (window + plan view already built, real load path, both print jobs through
  `run_print_view`, window snapshot to PDF + PNG), writes `smoke.json`, and exits
  non-zero if any check failed. **This half compiles only on `app-macos`, which has not
  run since 2026-10-22 because the Actions minutes are exhausted.** It is reviewed by eye,
  not by a compiler.

## The exact `--smoke` command line

```bash
# macOS (inside the .app bundle's executable; the app needs no install)
build-app/msproject_app.app/Contents/MacOS/msproject_app \
  --smoke tests/data/synthetic-base.mpp --out "$PWD/smoke-out"
```

* `--smoke <fixture.mpp>` and `--out <dir>` are required together; either missing prints
  a usage line and exits **2** without starting AppKit.
* The fixture is **`tests/data/synthetic-base.mpp`** (explicitly, not a generated
  project). It is **read-only**: `smoke_plan()` copies it to `<out>/smoke-input.mpp` and
  the plan is loaded from that copy; the save goes to `<out>/smoke-edited.mpp`. The run
  asserts both the fixture and the copy are byte-identical afterwards, and `app_smoke`
  asserts the fixture's size is unchanged.
* Exit codes: **0** every check passed; **1** a check failed (or the sequence could not
  finish — a missing fixture, a load/write failure); **2** bad arguments.
* Nothing outside `<out>` is written. No `NSUserDefaults` write: in smoke mode the
  preferences are reset to the defaults in memory only, so a developer's persisted
  preferences cannot change what the runner proves.

## The ten portable steps (and what each proves)

`app::smoke_plan()` runs these in order; every assertion is recorded with its step name,
so a failure reads `[save] the save wrote one row: got 0, want 1`.

| step | what it drives | representative checks |
|---|---|---|
| `fixture` | copy the committed fixture into the output dir | readable, output dir exists, copy byte-identical, artifact listed |
| `load` | reader → `PlanInput` → `RecordSet` → `SheetModel` → Gantt, exactly as `load_plan`/`build_editor`/`rebuild_view` do | 3 tasks / 3 assignments / 0 links, 3 RecordSet rows, 3 sheet rows, 3 visible rows, 3 Gantt bars, non-zero Gantt width, the sheet's Start cell equals `app::sheet_row_text()`, **the fixture's task 1 is stored manually scheduled**, no `114/Props` formula error |
| `filter` | the filter dialog model | every visible column is a filter field, operators populated, `ID >= 2` builds and matches 2 of 3, `restrict_to_filter` restricts the displayed rows, `filtered_record_set` keeps uids, an empty rule list is refused |
| `task_fields` | the Task Fields dialog model | six specs with ids/captions, initial Text text is empty, a typed value queues exactly one `set_field`, the display plan shows it, an unparsable date refuses the whole form and queues nothing |
| `predecessors` | the Predecessors dialog model | no incoming links in the fixture, `1 → 2 FS +1d` validates, queues, gives 4800 ticks, appears in the display plan and in `predecessors_of()` as pending, `make_link_delete` refuses a pending-only row, undo removes both queued edits |
| `start_edit` | a Start edited through `core::sheet` (begin/set/commit), then Cmd-Z/Cmd-Shift-Z | cell accepted + changed, cell text is the formatted date, `collect_start_edits` names the uid and date, undo empties the diff, redo restores it |
| `warning` | `warn_start_edits` / `warning_for_start_edit` / `start_edit_warning_text` | the real save **warns once** (the fixture's edited row is stored manual, and the writer converts it), a synthetic FS predecessor clamps an earlier start to the predecessor's finish + lag (the fixture has zero link rows, so that link is in-memory only), a manual task warns instead of clamping, an unchanged start is `no_effect` |
| `save` | `save_start_edits` (the real writer) | target == source refused with "refusing", 1 row written, writer path named, target exists, the accepted edits leave nothing pending, the edited bytes differ from the input, **the input copy and the committed fixture are byte-identical** |
| `reopen` | the written file read back | 3 tasks, 3 assignments, 0 links, same uid/name/duration per task, same title, the edited start is a **SNET constraint (type 4) with the typed date**, the manual row was converted to auto-scheduled, a fresh load has no pending edit |
| `print` | `build_print_job` for both kinds + `export_report` (File > Export PDF) | 3-row Gantt = 1 page / 35 rows per page, 3-row sheet = 36 rows per page, header/footer text, printer and PDF routes produce **identical** pages, a filtered job holds 2 rows, Export PDF's page count agrees with the print job's and writes `smoke-report-export.pdf` |

One wording caveat, so the table is not overclaimed: the shell has no separate controller

## What the smoke covers, and what it cannot

Covered (AppKit half, by construction — compiled and run only on `app-macos`):

* the window, its content view, the `PlanView` document view, and the real
  `-loadPath:`/`rebuild_view` result (3 tasks, 3 rows, 3 bars, columns laid out);
* `NSPrintOperation` with `NSPrintSaveJob` writing a real PDF for **both**
  `app::PrintKind` values, through the same `run_print_view` the File menu uses;
* the document view rasterised to PDF and PNG (`NSBitmapImageRep`).

Not covered, and not claimed:

* **a real printer** — no paper path, printer selection, duplex, tray or driver is
  exercised. `smoke-print-*.pdf` proves the save job, not the printer.
* **Retina / HiDPI** — the PNG is whatever backing scale the runner has (usually 1x);
  text metrics, line widths and the snapshot at 2x are unproven.
* **mouse feel** — clicks, double-click-to-edit, drag, shift-click extension, scroll
  physics, key repeat, IME/composition. None of that is driven.
* **multi-select** — the smoke never extends a selection or edits a range.
* **dialogs** — `NSAlert` (filter, save warning, insert/delete), `NSOpenPanel`,
  `NSSavePanel`, the Preferences panel: their *models* are tested (including by this
  smoke), their AppKit appearance and modality are not. In smoke mode `show_alert()` is
  a no-op by design.
* **the menu bar** — nothing is clicked; `app_menu` proves the data, not the NSMenu.
* **whether a CI runner has a window server.** If `macos-latest` has no GUI session, the
  AppKit steps fail (non-zero, artifacts may be missing) rather than hang. That would
  make `--smoke` unusable as a gate until a session is available; the portable half would
  still pass.
* **the writer's structural cascade** (insert/delete/field/link save) — that is
  `app_edit`, `app_edits_fields` and `app_edits_links`; this smoke saves start dates plus
  the dialogs' *decisions*, and does not write a structural file.

## Traps hit (W63)

- **The fixture's task 1 is stored as MANUALLY SCHEDULED.** `document_tests` prints the
  writer's receipt ("was manual; written as SNET and converted to auto-scheduled"). That
  means the smoke's real save **does** warn, and `warn_start_edits()` over the real edit
  is 1 manual warning, not 0. If a future fixture change makes the row auto, `app_smoke`
  fails on "the fixture's first task is stored as manually scheduled" — update the smoke
  consciously, do not delete the check.
- **The fixture has ZERO link rows**, so a clamped-start warning cannot be produced from
  the file. The clamp case is built on an in-memory copy with one synthetic FS link (uid
  9001) and an explicitly auto-scheduled successor; the check names say so.
- **`std::filesystem::path::string()` mixes separators** on Windows
  (`.../tests/data\synthetic-base.mpp`). Cosmetic in `smoke.json`; the artifact paths are
  absolute and valid.
- **`app_smoke` writes only under `build\w63-app\test-out\smoke`** (`run/` and `missing/`),
  never `tests/data/` or the repo root.
- **The Dropbox folder's mtime churn broke the `edit` tool repeatedly** ("file changed
  since it was read", even immediately after a read, including on files created in this
  session). Workaround: re-read the exact lines immediately before each `edit`, and use
  a throwaway Python patch under `build\w63-app\` for `app/README.md` (that file is CRLF
  and the patch asserts every anchor appears exactly once before writing).
- **`app/README.md` is CRLF**; the C++/`main.mm` files are LF. A `write` of the README
  would have silently converted it.
- **W64 edited `app/CMakeLists.txt` concurrently** (a `viewstate` cache var, `viewstate`
  in the `foreach` list, `core_viewstate` in `app_layout`'s link libraries). This stream
  re-read the file before each edit and left all three lines intact; a plain
  `cmake --build` with `viewstate` present succeeds.
- **`show_alert()` had to become a no-op in smoke mode.** Without it, a failed load would
  open a modal `NSAlert` on a runner and hang until the workflow timeout instead of
  failing with a check.
