# W47 handoff — app resource/usage views + computed columns (wave 11)

_2026-10-22. Stream W47 of wave 11. Owner paths used: `app/**`, `memory/app.md`,
`docs/handoff/w47.md`. Build tree: `build\vs-w47` only. No git commands were run;
everything is on disk in the main checkout for the coordinator to commit. `core/**`
was not modified; no core API was missing (the bridge is `core::usage::
usage_input_from_mpp` and `core::formula::ComputedColumns`)._

## What is done

The macOS shell gained the four-view model and read-only computed columns without
touching `core/**` and without adding task editing (wave 12's job).

1. **Model.** `app::PlanInput` now carries `resources` (`ResourceRow`: uid, id, name,
   initials, `core::view::ResourceType`, max-units percent) and `assignments`
   (`AssignmentRow`: uid, task uid, resource uid, work ticks, units percent, start,
   finish), mapped in `app/reader_adapter.h` from `mpp::Document`. `app::PlanState`
   carries a `core::usage::UsageInput` (built once per load through
   `core::usage::usage_input_from_mpp`), a `core::sched::Calendar`
   (`app::standard_calendar()`), the current `UsageProjection`, an `app::UsageView`,
   the secondary grid and the `core::formula::ComputedColumns`.

2. **Views.** `app::ViewMode` = Task Sheet / Resource Sheet / Task Usage / Resource
   Usage, switchable from **View ▸ (Cmd-Option-1..4)** and from a visible
   **NSSegmentedControl** in a control bar above the document, with a **Usage period**
   `NSPopUpButton` (Day/Week/Month).
   - Resource Sheet: rows from `core::view::build_resource_record_set` (ID, Name, Type,
     Initials, Max. Units) plus a Work column (assignment total in duration ticks). The
     Type is shown as its display name. Column captions/widths come from the registry's
     `resource-entry` table. Cost is not shown (no rates are decoded).
   - Task/Resource Usage: `core::usage::project_usage` rows as a sheet-like grid — one
     label column, day/week/month period columns, a **Total** column and a final
     **TOTAL** row of period totals. Period labels `Mon 19/10/26`,
     `Wk Mon 19/10/26`, `Oct 2026`.
   - Selection/editing/copy/undo/filter/collapse/Gantt zoom/PDF export are task-view
     only (`MenuState::task_view`); the other views are read-only and their clicks/keys
     are ignored cleanly. Save stays available (it still writes task starts).

3. **Computed columns.** Two read-only formula columns on the task sheet:
   `Number1 = [Duration]*2` ("Duration x2") and `Date1 = [Start]+7` ("Start +7 Days"),
   registered through `core::formula::ComputedColumns`, evaluated after every rebuild,
   declared read-only, refused by `begin_edit`, and outside the save diff (only task
   Starts are diffed). **View ▸ Columns** shows all 9 columns with check marks and a
   disabled "Stored custom fields (pending)" entry: `mpp::Task` exposes no stored
   custom-field values yet, so no column of invented zeroes is shown.

4. **Preferences.** `app::Preferences` gained `view`, `usage_period`,
   `formula_duration_column`, `formula_date_column`, `stored_custom_fields`; the one
   NSUserDefaults string is extended additively (`view=...;usage=...;formula1=0|1;
   formula2=0|1;custom=0|1`) and parsed tolerantly (unknown/bad/missing keys keep the
   default; a wave-10 string still parses). Version stays 1.

5. **Tests.** New `app/views_tests.cpp` (binary `app_views`, 164 checks): resource
   rows/fields/columns, usage day/week/month buckets + totals row/column + labels,
   formula evaluation, computed columns read-only + no save edit, view-mode
   identifiers, preference round trip (including a wave-10 string), formula-visibility
   helpers. `app/menu_tests.cpp` gained the four view items, three usage periods and
   `task_view=false` gating (664 checks). The existing seven binaries are green.

## CI risks in main.mm (ordered, new in wave 11)

1. **Control bar/container**: `contentView` is now a plain `NSView` containing a
   `control_bar` (`NSSegmentedControl` + label + `NSPopUpButton`) and the scroll view,
   with autoresizing masks (`NSViewWidthSizable`, `NSViewMinYMargin`,
   `NSViewHeightSizable`). Wrong mask/geometry would look wrong, not fail to compile.
2. **NSSegmentedControl construction**: `initWithFrame:`, `setSegmentCount:`,
   `setLabel:forSegment:`, `setWidth:forSegment:`, `setSelectedSegment:`; no
   `setSegmentStyle:` (deprecated constants avoided).
3. **Target/action**: `viewModeChanged:`/`usagePeriodChanged:`/`syncViewControls` are
   declared in the class extension-less `@interface` and implemented; `syncViewControls`
   is called at launch, after load and after every switch.
4. **Menu dispatch**: seven new `MenuAction` cases; the switch is still exhaustive over
   all 37 values (a missing case is `-Wswitch`).
5. **Per-view drawing**: `draw_plain_grid` (new) and the `draw_plan` branch; fonts and
   colours are the existing ones, no new API.
6. **Guards**: mouse/key/undo/redo/copy/paste/select-all/export early-return outside the
   task view; `MenuState::task_view` default `true` keeps the wave-10 enablement tests
   meaningful.
7. **ObjC string concatenation**: the new multi-line `@"..."` tooltip starts its second
   line with `@` (clang's `-Wobjc-string-concatenation` is an error in CI).

If CI fails it will name the line; everything risky is in `main.mm` and none of it is
reachable from the headless tests.

## Traps hit (also in memory/app.md W47)

- The `edit`/`write` tools kept failing with "file changed since it was read" on this
  Dropbox folder. Workaround: read immediately before writing; for the big patches a
  throwaway Python script under `build\vs-w47\` with `str.replace(old, new, 1)` and a
  `count == 1` assertion (32 replacements in `main.mm`, 20 in `README.md`). Nothing was
  written outside `app/**`, `memory/app.md`, `docs/handoff/w47.md`, `build\vs-w47`.
- `core/usage` and `core/formula` are not part of the app's core-subdirectory list by
  default; add them with `*_BUILD_TESTS=OFF` (order: usage after sched, formula after
  sheet) or `view_model.cpp` fails to link.
- `usage_mpp.h` includes `reader.h`; including it from `reader_adapter.h` preserves the
  "only one app file includes the reader" rule.
- Usage grid columns use app-private field ids (`0x0b4f0001/2`, periods
  `0x0b4f1000+i`); every column therefore carries an explicit title.
- `app::cell_text` now applies the duration-style preference to any `Duration` cell, not
  only the task Duration column, so the usage grids honour hours/days mode.
- The task sheet's column set is fixed at 9 (7 default + 2 computed) so the dynamic
  View ▸ Columns submenu's `tag` stays valid; `default_sheet_columns()` deliberately
  remains 7 for the existing tests/export.
