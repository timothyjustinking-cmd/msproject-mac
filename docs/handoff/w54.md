## What is done

The structural writer is complete for the Task, Link, Resource and Assignment
tables. W54 adds:

- `mppwrite::add_resource_row(doc, ResourceSpec, path)` — appends one
  `114/TBkndRsc` resource row + its FixedMeta/Fixed2Data/Fixed2Meta entries and
  five VarMeta/Var2Data payloads.
- `mppwrite::add_assignment_row(doc, AssignmentSpec, path)` — appends one
  `114/TBkndAssn` assignment row + FixedMeta/Fixed2Data/Fixed2Meta entries and
  four VarMeta/Var2Data blocks.
- `mppwrite::delete_assignment_row(doc, uid, path)` — tombstones an assignment
  row (FixedMeta entry `+0 = 0x02`, `+2 = 0`; table header `+4 |= 0x02`), no
  stream shrinks.
- `tests/roundtrip_assignments.cpp` — 679 checks, 0 failures, plus three
  fixtures + manifest and a corpus-gated control on `w12-assignadd.mpp`.
- `core/mppwrite/CMakeLists.txt` — new `mppwrite_roundtrip_assignments` target,
  reader link when the top-level build provides `core_mpp`, fixture mirror moved
  to `core/mppwrite/build/vs-w54/test-out`.

All three entry points are all-or-nothing: validate -> copy -> apply -> save ->
re-open from disk -> re-read every row/entry/identity/block -> require
`check()` and `check_table()` clean -> replace the caller's document. A refusal
happens before `doc` or the output path is touched.
