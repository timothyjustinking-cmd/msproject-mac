## Deliverables

### 1. Resource Type / MaxUnits exposure — DONE (measured)

`core/mpp/reader.h` / `reader.cpp` / `tests/mpp_reader_tests.cpp`.

Resource Type is **not** a byte in the 172-byte row; it is per-row metadata:

* `TBkndRsc/FixedMeta` entry byte **+12 bit 0x10** set => Work.
* bit clear + `TBkndRsc/Fixed2Meta` entry byte **+8 bit 0x10** set => Cost.
* both clear => Material.

The two metadata streams pair by **entry index** (the Fixed2Meta +4 word is a
Fixed2Data record offset, not the FixedMeta row offset), like the Task outline.

Measured on the COM-built `corpus/probe/w9-resourcetypes.mpp`:
Work 50 % / Material (MaterialLabel) / Cost decode as
`ResourceType::work/material/cost` with `type_stored == true`; PROJECT_A 22/22 and
PROJECT_B 22/22 resources decode Work, matching their MSPDI exports.
`Resource::material_label` is VarMeta `0x0c40012b` (the synthetic probe's
"metre"). `is_material()` / `is_cost()` added.

**MaxUnits scale is now measured**: R1's COM MaxUnits 50 % is the double
**5000.0** at +8, so the scale is x100 (10000.0 = 100 %), not x10000.

Measured vs inferred:

* MEASURED: the three type words on w9-resourcetypes, the Work result on
  22+22 PROJECT_A/PROJECT_B rows, MaxUnits 5000.0 = 50 %, material label key.
* INFERENCE/OPEN: the Project-2010 MPP14 variant stores the Work bit at
  FixedMeta entry +9 bit 0x02 (mpxj layout); no such file is on disk, so it is
  not implemented. MSPDI `<Type>` is a different enum (1 = Work, 0 = Material,
  cost via `IsCostResource`) and must not be compared numerically.
  `tools/mspdi_cmp` still only understands Type=1 Work and is not used on
  w9-resourcetypes.

## Traps

* Task DurationFormat is +0xa4, not a VarMeta field; `+0xa4 == 8` means elapsed
  days, while 7/9/11 are working days/weeks/months and 21 is "no format".
* Resource Type is metadata, not a row byte. FixedMeta entry +12 bit 0x10 is
  Work; Fixed2Meta entry +8 bit 0x10 is Cost. Pair the two streams by entry
  index, never by their +4 offsets.
* `from_mpp` cannot build calendars; `attach_task_calendars` is a required
  extra call for any path-bearing consumer. uid -1 must stay on the project
  calendar.
* `core_plan` links `core_cal` PUBLIC now. Do not "fix" that by moving the
  attach call into tests only.
* The elapsed-duration row must not change PROJECT_A/PROJECT_B: their +a4 values are
  7/9/11/21 only, and their +178 is -1 on every task. Both are asserted.
