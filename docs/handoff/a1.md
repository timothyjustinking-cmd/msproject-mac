## 2. The save path, exactly

`-[AppDelegate saveDocumentWithPanel:]` (main.mm, the one path Save/Save As and
the close prompt use):

```cpp
const bool document_edits = plan.document != nullptr && plan.document->has_pending_edits();
...
if (edits.empty() && !structural && !document_edits) { "nothing to save"; return YES; }
...
if (structural) { return [self saveStructuralEdits:edits target:target]; }

app::SaveOptions options;
options.allow_source_overwrite = plan.owns_path;
const app::SaveOutcome outcome = plan.document->save(edits, target, options);
```

`Document::save(start_edits, target)` is W64's combined path: it opens the source
container once, calls `apply_document_edits()` (formula, then `214/CTable`), then
runs `mppwrite::save_date_edits()` on that same `CfbDocument` — **one container
write, then the existing reload/accept of the start edits**. Date-only saves are
byte-identical to the old `save_start_edits` path (the same writer is called with
the same edits; `document_tests`' 169 checks, including
`test_save_start_date_with_view_and_formula`, still pass). After a successful
write the app discards both pending operations and updates `g_target_path`,
`plan.loaded` and the dirty dot exactly as before.

**The structural path is not one write.** `app::save_structural_edits()`'s
cascade (`app/edit_model.cpp`, not this stream's lane) has no seam for
`apply_document_edits()`, so the pending table format/formula cannot ride that
container write. A1 does the smallest correct thing instead of dropping them:
after the cascade writes `outcome.path`, it opens a fresh
`app::Document(outcome.path)` (allow_source_overwrite, the file is ours), copies
the pending `ViewStateEdits`/`CustomFormulaEdit` from the old Document, writes
them, and only then reloads. It is a **second, byte-disjoint write** — the
field-value-before-formula ORDER is still preserved because the second write
re-reads the file the cascade wrote, so the `0x02401392` decision sees those
values. If that second write fails, the structural file is still written and the
status line + an alert say the pending document edit was not written (it is not
silently dropped). Lines: main.mm 3982–4036.

**What is still unreachable (the report's save-order case):**
1. **One write** for structural + document edits. Only a real in-cascade seam in
   `app/edit_model.cpp` (`apply_document_edits(cfb_document, view, formula)`
   after step 5) makes that one write; A1's second write is the fallback.
2. The **"field-value writers first, then `apply_document_edits`"** ordering in
   the same `CfbDocument` (w64.md §5) is unreachable from the non-structural
   path: no custom-field **value** writer runs there. The formula flag can only
   see values already in the source file, not values written in the same save.
   Only the structural fallback (via the written file) achieves that ordering,
   and only on the second write.
3. `Document` has no `SaveOutcome` path that both writes structural edits and
   these two operations; W64 says so explicitly (document.h lines 159–163).

## 3. The two commands (labels are the user-visible contract)

| menu | item | key | enablement (`menu_item_enabled`) |
|---|---|---|---|
| View | `Table Date Format...` | none | `has_document` (a `214/CTable` table definition is a file property, not the view on screen, so it stays enabled in the resource/usage views) |
| Edit | `Custom Field Formula...` | none | `has_document && task_view && !editing` (a Task custom field, chosen in the dialog, so no row selection is required) |

- **No "Task" or "Field" menu exists** in this shell. Its custom-field commands
  live in Edit (`Task Fields...`, `Predecessors...`), so `Custom Field Formula...`
  was put there, after `Predecessors...` with a separator — not invented as a new
  top-level menu.
- **Table Date Format...** offers **4** (`PjDateFormat` = `pjDate_mmm_dd_hh_mmAM`,
  label `4 - mmm dd hh:mm AM`) and **5** (`pjDate_mmm_dd_yyy`, label
  `5 - mmm dd 'yy (measured)`). Only **5** is measured as a written byte
  (w56.md §8.2 / oracle `DateFormat=5`); 4's UI meaning is the type library's
  enum name (`analysis/typelib.tsv` lines 22–23), not a reopened save. The alert
  says so in the dialog text (`(measured)`) and in the code comment. The command
  sets `ViewStateEdits{set_date_format, date_format, table_index=0}` and keeps any
  other pending view-state operation.
- **Custom Field Formula...** has an accessory `NSView` with an `NSPopUpButton`
  of seven Task custom fields (Text1/Text2/Number1/Number2/Duration1/Date1/Flag1)
  and one `NSTextField` for the formula text. Buttons: **Set Formula**,
  **Clear Formulas**, **Cancel**. Set goes through
  `Document::apply_custom_formula(field_id, text)` (an empty formula is refused
  there and the alert shows its `error`); Clear goes through
  `Document::clear_custom_formula()` (whole formula table — `core/props` has no
  per-field clear, measured empty form).
- Both commands call `[g_view refreshAfterChange]`, so the window's document-edited
  dot, the menu validation and the status-line `pending:` fragment update at once.
  Neither opens a new window.

## 8. Traps hit

- **The Dropbox mtime churn broke the `edit`/`write` tools again** ("file changed
  since it was read", including files created in this session, and once on
  `build\a1-app\patch_a1.py`). Workaround used: Python scripts under
  `build\a1-app\` that assert every anchor appears exactly once and write only if
  all anchors matched (all-or-nothing), preserving CRLF/LF; `app/main.mm` and the
  menu files are LF.
- **`app/menu_model.cpp` changed between the read and the patch**: `Predecessors`
  gained its `"Predecessors..."` title. The anchor check caught it and refused to
  write; re-read and adapted. Do not trust a cached read in this folder.
- **`menu_tests` counts grow non-linearly** with menu items (per-menu pair loops).
  The +58 is expected; do not "fix" the count by deleting checks.
- **`cmake --build` without `--parallel` can still hit a transient MSB6003
  (tlog in use)** right after a ctest run; retry once before suspecting code.
- **`PlanState` is assigned `PlanState{}` in `load_plan`**, so the new Document
  holder had to be a `unique_ptr` (a plain `app::Document` member would delete the
  default constructor and break that assignment). `document.h` is not this
  stream's lane, so its API was not grown.
