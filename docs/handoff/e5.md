Stream E5 of wave 20 on the C++ port of MS Project. Target: the engine dump's

## 1. The measured rule

Project's stored late pair for a **manual** row is **the row placed at its
latest**, not the CPM late pair and not the inverse of `manual_finish_of()`:

```
late finish = min( project finish,
                   min over outgoing FS links of  successor KEPT start - lag,
                   min over outgoing FF links of  successor KEPT finish - lag )
late start  = max( kept start,
                   calendar-walk the Duration back from late finish )
```

where "calendar-walk … back" is `Calendar::sub_work` (the plain backward walk,
**not** `align_back`), and the FS/FF subtraction is that same plain walk. An
SS/SF outgoing link does not bound the row's late finish (it bounds the
successor's placement), and no measured row has an elapsed lag.

The three slack words do **not** change: they remain the effective pass's
(`TotalSlack = LF − EF` on the effective dates, `StartSlack = TotalSlack`). The
stored pair is a separate stored field (as E4's dump comment said); the difference
between it and the CPM pair is normally the lunch break, which is zero working
time, so both read the same slack.

directions: `duration-change` needs LF **earlier** (01-07 not 01-09) and

### What refuted the alternatives

* **`LS = kept start`, `LF = CPM late finish`** (what the applier kept): fails
  duration-change/delete (the CPM LF *did* move) and the clamp rows
  (recalculate uid2 stores 01-06, not its 01-04 start).
* **`LS = inverse of `manual_finish_of()` at LF`**: duration-change's uid 3
  (01-05 13:00) and delete's uid 1 (01-09 13:00) agree, but link-fs-lag uid 1
  has no inverse at LF 01-09 13:00 within the 13:00 family (the exact inverse
  would be a 15:30 kept start) and the row stores its kept start instead.
  The clamp explains it; a pure inverse cannot.
* **`LF` = CPM late finish with the engine's finish-side alignment**: gives
  01-09 12:00 for link-fs-lag uid 1 (oracle 13:00) and 06-02 17:00 for
  PROJECT_B 10762 (oracle 06-03 08:00). The manual row's predecessor bound is
  the *plain* subtraction from the successor's kept date.
* **`LF` from the successor's LATE start**: PROJECT_B 10775 rules it out
  (succ late start 09-10 08:00 vs stored 08-26 08:00).

### Inference boundaries (stated, not hidden)

* **FF** uses the successor's kept finish by the same "kept successor" principle
  — no measured manual row has an FF link. SS/SF are measured not to bound LF
  (W12 uid 1).
* **Elapsed lag** on an outgoing link: no measured manual row; such a row keeps
  the CPM pair and is counted in `PlanResult::manual_late_unmodelled`.
* **Task calendar**: every measured manual row is on the project calendar; the
  walk uses the row's own calendar if one is set (`[I]`).
