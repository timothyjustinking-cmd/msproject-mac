# Wave 33b verification review

Scope: `wave33` = `da5f4da` to `wave33b` = `bde04b3` (13 commits, 25 files). The reviewer worked read-only: nothing was built or run in the repo. Commands used: `git diff/show/grep/log`, `python -I scripts/check_markers.py --range main..wave33b` and `--range wave33..wave33b`, and `gh run list/view` plus the job-log API for the tip's CI. For one check, two committed fixtures had their `214/CTable` streams extracted with olefile into the session scratchpad, outside the repo, and dumped with an already-built `viewstate_report.exe` from `build/review-w32-app` (read-only).

## Verdict

All three review findings are closed in the code. **R33-1:** the date-format write for a table index other than 0 is refused in both shells, in `Document::request_view_state_edits` and in the save hook (`apply_view_state_edit`). No other caller in the tree reaches `set_table_date_format` with a non-zero index (`tools/oracle_gate` uses table 0). The table-0 write is unchanged, and both the app and Qt tests assert the measured shape: exactly one `Var2Data` byte changes, at payload +7, to 0x05. **R33-2:** `Operation::clear` is refused in the save hook before `114/Props` is read, and the cascade test asserts the refusal and a byte-identical target. **R33-3:** the macOS Task Fields handler now uses the Qt trial-queue pattern, and the tip's `app-macos` CI run compiled it. The CI-1, CI-2 and CI-3 fixes are correct. The `plan.cpp` counter had no reader, so its removal changes no output. The CI-2 sweep also restores the `CAL_NO_CORPUS` / `MPP_NO_CORPUS` skip switches, which is disclosed and is not a weakening: every gated path is under git-ignored `corpus/`. The diff weakens no gate: no workflow change, no ctest exclusion, no tolerance change, no expected-failure growth. The one removed test leg tested only the now-refused clear heuristic, and the record discloses its removal. The privacy check is clean.

I found **no Critical and no High**. There are two Mediums. First, the model-level backstop guards only the date-format operation, so a hand-built column replace on a non-zero table still reaches an unmeasured write (R33b-1). Second, the tip's `ubuntu-asan` CI job is red: 6 of 55 tests fail. These are faults the job exposed (it reached its tests for the first time); the wave 33b diff did not cause them. The brief makes such failures G0 items of this wave, and the merge rule needs green CI (R33b-2). Every other tip CI job is green.

Counts: Critical 0, High 0, Medium 2, Low 3.
