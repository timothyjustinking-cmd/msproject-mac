## 1. What is done

### Insert / Delete Task (deliverable 1)

| file | what it holds |
|---|---|
| `app/edit_model.h` / `.cpp` (new) | `StructuralEdit` / `StructuralEdits`: the pending edits, their undo/redo, `apply(loaded)` (the display plan), `without_structural_edits(shown, loaded)` (the inverse used by a rebuild so a pending Start edit is not lost), `count_delete_dependants()`, `next_placeholder_uid()`, `save_structural_edits()` |
| `app/menu_model.h` / `.cpp` | `insert_task` is now supported and enabled (Cmd-I in the Insert menu); new `delete_task` action in the Edit menu (Cmd-Backspace); `insert_resource` and `cut` remain permanently disabled with a reason |
| `app/document.h` / `.cpp` | `collect_start_edits` now matches by UniqueID (a pending insert has no file row; a pending delete is not displayed); new `SaveOptions::allow_source_overwrite` (default false, so the old refusal is unchanged) |
| `app/main.mm` | `PlanState::{base,edits,file_formulas,formula_set,owns_path}`; `build_editor`, `apply_structural_change`, `-insertTask:`, `-deleteTask:`, `-saveStructuralEdits:target:`, `-rebuildColumnsMenu`, two-stack undo/redo; the status line names pending edits; the close prompt names both kinds of pending edit |

Behaviour: Insert asks for a name, records a pending insert anchored on the selection (or
at the end), and the row appears immediately (`apply()` clones the file's last live row's
dates — the writer's documented add shape — and shows the name). Delete asks for
confirmation naming the dependant count (links naming the uid + assignments for it) and
removes the row plus its displayed links/assignments. Delete on a pending insert drops the
insert. Nothing touches the file until Save.

On Save the writer applies the whole set: `mppwrite::delete_task_row` per delete (the task
plus its link/assignment cascade), `mppwrite::add_task_row` per insert (the writer
allocates the uid), then the pending starts through `mppwrite::save_date_edits` — one
Save, one file. The app **reloads the target and adopts it** (`owns_path = true`); the
added uids/ids are the file's and are never patched by hand. The file the user opened is
never modified: `save_structural_edits` refuses `target == source` unless it is the app's
own reloaded file.

Undo/redo: a structural edit rebuilds the sheet (a new `SheetModel`, so its cell-edit
history ends); Cmd-Z prefers the sheet's stack and otherwise undoes the last structural
edit; a cell edit clears the structural redo list. Documented in `app/README.md`.

### Stored custom-field columns (deliverable 2)

- `app/layout_model.h/.cpp`: `TaskRow::custom_fields` (`mpp::CustomFieldValue`),
  `TaskRow::custom_field(id)`, `app::value_of_custom_field()` (Text/Number/Date/Duration/
  Flag decode; absent, unmeasured and not-set values are Null), and `make_record_set`
  adds every stored field to the schema and writes its value.
- `app/reader_adapter.h`: `task_row_from_mpp` copies `task.custom_fields`;
  `props_stream_from_file()` reads `114/Props` from the CFB (empty when absent).
- `app/fields_model.h/.cpp` (new): the six column specs from the registry
  (`mpp::custom_field_id(kind, n)`: Text1 `0x0b400033`, Number1 `0x0b400057`, Number2
  `0x0b400058`, Date1 `0x0b400109`, Duration1 `0x0b400067`, Flag1 `0x0b400048`), captions
  from the descriptor table, the complete editor column set, read-only enforcement and
  preference-driven visibility.
- Formatting: the stored columns are ordinary `RecordSet` fields, so `app::cell_text`
  applies the date-format and duration-style preferences and flags render `Yes`/`No`.
- They start hidden (`custom=0`), toggled per column from View ▸ Columns.

### Formula columns from the file (deliverable 3)

- `read_file_formulas(props_bytes)` → `core/props` `parse_props` + `extract_formulas`
  (the six measured blocks), mapped by field id and kept verbatim (the `[MSPJ<decimal>]`
  tokens are what `core::formula` parses). A non-Task field, a duplicate target or a
  formula that does not parse is a warning, not a failure.
- `formula_columns()` puts the file's formulas first and adds the two wave-11 demo
  columns only for a field the file does not define (one column per field).
- `build_computed_columns()`/`evaluate()`/`value_of_field()` are the same core path as
  wave 11; `app::apply_formula_read_only` marks them read-only and the save diff never
  sees them.
- `[Start]` is stored as StartText `0x0b400505` (measured in `memory/props.md`), which
  `core/formula` has no fallback for (only DurationText has one), so `make_record_set`
  fills StartText/FinishText from Start/Finish. **Inference** — the token ids are
  measured, the fallback semantics are not. Flagged in `memory/app.md` and the README; a
  core-side fallback would be the cleaner fix (coordinator decision, `core/**` not mine).

### Preferences (deliverable 4)

`app/prefs.h/.cpp`: `ColumnVisibility {field, visible}` + `Preferences::column_visibility`;
`column_visible()` / `set_column_visible()` (a choice equal to the default removes the
override); serialized as the additive `columns=0x0b400033:1,0x0b400057:0` key in the one
existing NSUserDefaults line; the parser skips a malformed entry. `custom=0|1` remains the
stored columns' default. `app/main.mm` persists a custom/formula column toggle through
this API; ordinary columns are unchanged.

## 6. Traps (do not re-learn these)

- **`synthetic-base.mpp` has 3 tasks, 3 assignment rows and 0 link rows.** The file-level
  delete-cascade test proves the assignment half; the link half is proved in the pure
  model. Do not "fix" the fixture.
- **The `edit`/`write` tools race Dropbox's mtime churn** on this folder. Use a throwaway
  Python script under `build\vs-w51\` with exact `str.replace(old, new, 1)` and a
  `count == 1` assertion; check EVERY anchor before writing (a script that writes while
  later anchors fail leaves a half-patched file).
- **`mpp::Task::custom_fields` always has Flag1** for a live row (a clear bit is a stored
  False) — "No" everywhere is correct, not a bug.
- **`[Start]` is StartText (`0x0b400505`), not Task.Start (`0x0b400023`).** The app fills
  StartText/FinishText in `make_record_set`; `core/formula` has only a DurationText
  fallback.
- **`add_task_row` appends and clones the last live row.** A cell typed on a placeholder
  other than its name is not written; the save message says so. Do not patch a uid after
  a write — reload.
- **Adding `core/props` to `app/CMakeLists.txt` also builds its `props_report` tool**
  (`PROPS_BUILD_TESTS=OFF` only skips the test). Harmless; mentioned so it is not a
  surprise.
