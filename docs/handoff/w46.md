## What is done

The macOS shell grew from "display + edit + save" to a menu/preferences/export
application, without touching `core/**` (no core API was missing):

1. **Menus.** The whole menu bar is data (`app/menu_model.{h,cpp}`): App / File /
   Edit / View / Insert / Help, 30 `MenuAction`s, key equivalents, and enablement
   rules. `main.mm` walks it and dispatches through one `performMenuAction:` switch.
   `Insert > Task`, `Insert > Resource` and `Cut` are present, permanently disabled
   and carry the reason (`menu_disabled_reason`), because the writer cannot grow a
   table, there is no resource table, and `SheetModel` has no cut. Copy/Paste are
   wired to `NSPasteboard`; Select All to `SheetModel::select_all`.
2. **Preferences window** (`app/prefs.{h,cpp}`): date format, duration format,
   timescale (day/week/month), working-day shading. Applied live to the sheet and
   Gantt; persisted app-side in `NSUserDefaults`
   (`com.msprojectdecompile.shell.preferences`) as a tolerant one-line string.
   `app/README.md` documents why: the oracle measured that Project exposes no global
   date/duration/timescale setter and that a table date format lives in `114/Props`;
   nothing is faked into a `.mpp`.
3. **Export PDF** (`app/export_pdf.{h,cpp}`) through `core/render`: sheet and Gantt
   reports, the filtered rows, the visible columns, the preference date format and
   duration style, and the shading preference (all-working calendar when off). The
   current selection is named in the report footer (core/render has no selection
   concept; not highlighted, and the README says so).
4. **Filter dialog** (`app/filter_model.{h,cpp}` plus an AppKit alert): column /
   operator / value with Apply / Clear / Cancel; a value is parsed with the same
   parser the cell editor uses and errors name the field. Applying a filter restricts
   the **displayed row list** (`app::RowMap`), never the `RecordSet`, so editing,
   undo and the save diff are unaffected. The model also builds All/Any trees of
   several rules (tested); the dialog authors one criterion this wave.
5. **Dirty state + prompts.** The document is dirty exactly when a save would write
   something (edited task starts — the only thing `core/mppwrite` persists), so the
   window's edited dot is honest. Close/Quit with pending edits asks Save / Don't
   Save / Cancel with `windowShouldClose:` + `applicationShouldTerminate:`; the
   prompt says the other edits are view-only. Save remembers its target, Save As
   always asks, and `SaveResult::warnings` are surfaced in the status bar plus an
   alert.
6. **Keyboard.** Arrows/Tab/Return/Esc/Backspace as before, plus **Space** to toggle
   between one cell and the whole row, the menu zoom (Cmd-= / Cmd--, Cmd-1/2/3), and
   filter/clear-filter/shading/save/export key equivalents.

New headless tests (all pass on Windows): `app_prefs` 82 checks, `app_menu` 457,
`app_filter` 60, `app_export` 58 (writes real PDFs, byte-determinism included).

## CI risk in main.mm (read before the first run)

Ordered by likelihood:

1. **Menu construction**: `installMenu` walks `app::menu_specs()`, sets
   `setAutoenablesItems:NO`, sets the submenu delegate, and creates the dynamic
   Columns submenu. A mistake here fails compile or leaves items disabled.
2. **`NSMenuItemValidation` / `NSMenuDelegate` conformance** on `AppDelegate`
   (`validateMenuItem:`, `menuNeedsUpdate:`).
3. **Preferences panel** control construction (`NSPopUpButton`
   `initWithFrame:pullsDown:`, `NSButtonTypeSwitch`, `secondaryLabelColor`).
4. **Filter `NSAlert` accessory view**: three subviews, three buttons, and the
   `NSAlertFirstButtonReturn`/`Second` dispatch.
5. **`UTType` in the export save panel** (`typeWithIdentifier:@"com.adobe.pdf"` inside
   `@available(macOS 11.0, *)`).
6. **Close/quit hooks**: `windowShouldClose:` on the delegate that is also the app
   delegate, and `applicationShouldTerminate:` returning
   `NSTerminateNow`/`NSTerminateCancel`; `g_close_confirmed` prevents a double prompt.
7. **ObjC string concatenation**: every `@"..."` continuation line starts with `@`
   (clang's `-Wobjc-string-concatenation` would be an error).
8. **`NSOpenPanel`/`NSSavePanel` `setAllowedContentTypes:`** — pre-existing pattern,
   already used by the working v2 job.

If CI reports a warning/error, it will name the line; all the risky code is in
`main.mm` and none of it is reachable from the tests.
