# Q3 handoff — the Qt shell's visible deltas against MS Project (wave 18)

Date: 2026-10-23.  Owner: stream Q3.  Status: **delivered, not compiled here**
(Qt 6 is not installed on this machine and installing is forbidden; the
coordinator compiles via the `qt-linux` CI job).  Files owned/changed:
`app_qt/**` and this handoff only.  No git command was run; `scripts/**`,
`docs/parity.md`, `corpus/**`, `app/**`, `core/**`, `tests/**` and
`.github/**` were not touched.

The starting point was Q2's state: 8 comparable measures and 0 failing at
900x560, but with four visible defects (clipped ribbon labels, `Ta…` bar
labels, a scrolling row-number gutter, no parity-sized render) and no column
width comparison at all.

## 1. The five deltas, and what closed each

| # | delta (visible in the 900x560 render) | fix |
|---|---|---|
| 1 | ribbon labels clipped to `Cu`, `op`, `t F` | every ribbon button gets a **fixed width from its own label's QFontMetrics** (+12 px for the stylesheet's 5 px padding/border each side, never below the style's own size hint); the group's width follows its widest child.  A window too narrow for a whole group now **drops that group and every group after it**, so a label is never half-drawn: Qt's `QToolButton` clips text from both ends when squeezed.  At 900 the Task tab shows View/Clipboard/Font/Schedule whole; at 1920 all eight groups fit (≈1617 px with Calibri).  Height stays 105 px and tab/group order is unchanged. |
| 2 | bar labels truncated (`Ta…`) | the shell now decides placement from the **real font**: a label whose text + 4 px padding either side fits the bar is drawn centred, white, **inside** it; otherwise it is drawn to the right of the bar in body text, elided only at the canvas edge.  "Task A" is ~36 px and fits the fixture's 5-day bar (120 px at 24 px/day).  The old code elided to the model's 7 px/char rect (`42 - 2*3 = 36 px`), which cut the real 36.4 px text. |
| 3 | row-number gutter scrolled with the sheet | the gutter is now the view's **frozen vertical header** (`SheetRowHeader`, 60 px), the Qt-native frozen row header, instead of model column 0.  The model exposes exactly the nine Entry columns.  The sheet's left border is painted on the **viewport** (`SheetView::paintEvent`) so it stays at x = 60 while the columns scroll under it; the caption-band corner is a white child widget (QTableView paints cells on the viewport, so a second painter on the view is not a supported device). |
| 4 | no parity-sized render | `--parity` (= `--render-size 1920x1032`) on the CLI.  The **default window stays 900x560**; only the render size changes, and `--render` still fails if the pixmap is not the requested size.  New CTest `qt_render_parity` writes `build-qt/test-out/qt-render-parity.png`, which the existing artifact glob already uploads (with `qt-render-document.png`). |
| 5 | column widths N/A at 900 / ninth column clipped at 1920 | at 1920 the nominal 0.459 split (881 px centre) leaves the sheet pane 878 px, one pixel short of the table's own 879 px (gutter + nine columns), so the ninth column's last pixel was clipped.  `apply_split_fraction()` now snaps the pane to the whole table when the shortfall is at most one handle and the chart keeps its 240 px minimum (1920: 878 → 879); on a narrower window the fraction still governs and the table clips as Project clips.  A queued re-apply after the layout makes this deterministic on interactive resizes too.  The widths themselves were already data-driven and correct (`214/CTable chars*6+3`): 6/9/24/13/13/13/17/17 + the 20-char stub → 39/57/147/81/81/81/105/105/123. |

The mock's sheet columns are `[38, 57, 147, 81, 81, 81, 105, 105, 124]`; the
real Qt render is expected to be one of

* `[38, …, 124]` — if Qt draws the vertical grid on the cell's last pixel
  (the convention read from `qtableview.cpp`), or
* `[39, …, 123]` — if the frozen gutter's border and the first column's left
  edge coincide differently,

i.e. a **−1 on the first column and +1 on the last, or exact everywhere**: the
sheet's left edge is the gutter border pixel and the right edge is the
splitter's left line, so the measured span is 820 px against the reference's
819.  Both are well inside the ±4 px tolerance and neither is a column width
error.  If the CI render reports any per-column delta outside ±2 px, that is a
real bug (a width not applied), not this pixel convention.

## 4. What still differs (honest list)

1. **Ribbon icons** are out of scope (text/glyph only, as the brief says); the
   buttons are text buttons with a white background, not the product's artwork.
2. The **first/last sheet column** may measure ±1 px from the gutter-border /
   splitter-line convention (section 2).  Everything in between is exact.
3. The nine column widths are exact in the mock and data-driven in the real
   shell; if CI's `214/CTable` readback ever fails, the stock character widths
   produce the same 819 px set (Q2's caveat, unchanged).
4. The fixture has **three tasks**, so below its last row the Qt sheet is blank
   white while the reference capture rules empty rows to the bottom.  P1's
   harness measures the body band and the column lines, not the region below
   the last row, so this does not affect the score; it is a fixture-size
   difference, not a shell defect.
5. **Task bar colour** is still unmeasured (the reference has no bars), and the
   bars in the fixture are drawn in the shell palette.
6. The 1920 **column-width** sentence in this handoff is proved by the mock;
   the real PNG will exist only after the coordinator's CI run.

## 6. What was not compiled, and the likeliest CI errors

Nothing here was through a compiler: there is no Qt 6 on this machine.  The
code was written to Qt 6.2 Widgets only (no `Q_OBJECT`/AUTOMOC, no new
third-party code), and the non-Qt parts (`entry_columns`, `plan_document`) were
not touched.  Risk list, most likely first:

1. **`QMetaObject::invokeMethod(this, lambda, Qt::QueuedConnection)`** in
   `MainWindow::resizeEvent` — the functor overload needs Qt ≥ 5.10 (fine for
   6.2) and `<QMetaObject>` is included.  If a toolchain rejects the overload,
   replace it with a one-shot `QTimer::singleShot(0, this, [this]{…})`.
2. **`SheetRowHeader::paintEvent`** calls `QHeaderView::paintEvent` after its
   own painter is destroyed (the painter is scoped).  If a Qt version warns
   about nested painting there, painting is already done; the base call could
   be dropped and the sections painted by `paintSection` alone.
3. **`QTableView::setVerticalHeader`** is public but changes the view's
   geometry; if the header's width comes out as something other than 60,
   `SheetRowHeader::sizeHint()` (which pins 60) is the place to look first —
   `updateGeometries()` uses `qMax(minimumWidth, sizeHint().width())` clamped
   by `maximumWidth` (all three are 60 via `setFixedWidth`).
4. **`--parity` parsing** uses `std::strtol`; `--render-size 1920x1032` is
   validated 200..8192 per side, and the usage text lists both.

## 7. Traps for the successor

1. **The row header is the gutter.**  The model's column 0 is now Indicators;
   every display-column index is one less than it was in wave 17 (the delegate
   maps, `configure_sheet`, `sync_view_selection`, both tests).  A stray `+1`
   silently shifts every column and the harness will report the widths against
   the wrong boundaries.
2. **The sheet's left border is the viewport's first pixel**, painted by
   `SheetView::paintEvent`, *not* the row header's right edge — that is what
   puts the measured sheet edge at 60 and keeps it there while scrolling.  Do
   not add a border to `SheetRowHeader` (it would make a 2 px line and move the
   first width by one).
3. **The corner is a child widget**, because `QTableView::paintEvent` holds a
   painter on the viewport and Qt does not allow a second painter on the view
   from inside it.
4. **Don't let a ribbon group shrink.**  `QToolButton` elides/clips from both
   ends; the whole-group overflow (`layout_page_groups`) is the only correct
   answer.  The 8 pt label widths are metric-derived, so a font change (Carlito
   on a developer machine vs DejaVu in CI) changes the total and therefore how
   many groups fit — never the fact that a visible one is whole.
5. **The bar-label padding is `GanttStyle::label_gap` (4 px)**, not the old
   `kLabelInset = 3`; keep them in step if the model's default changes.
6. **The 1920 render must keep the 900x560 default.**  `--parity` only changes
   the render size; the tests parse "rendered 900x560" and "rendered
   1920x1032" as separate promises.
