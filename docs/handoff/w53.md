### 1. Model / decode — DONE (measured)

Fixture: `corpus/probe/w12-exceptions.mpp`, one exception of every
`PjExceptionType` on the project calendar; COM ground truth in
`docs/analysis/oracle/w12-exceptions.json` (identical before save and after
reopen). Independent second opinion: mpxj
`AbstractCalendarAndExceptionFactory.readRecurringData` (same words, same
meanings; fetched read-only, not vendored).

The parameters are the seven `u16` words at **+74..+86** of the 92-byte exception
record.  Measured layout (byte views at `+76` low/high, `+77`, `+78`):

| type | +76 low | +77 | +78 |
|---|---|---|---|
| 1 daily, every day | 0 | 0 | 0 |
| 2 yearly month+day | Month-1 (2 -> March) | MonthDay (15) | 0 |
| 3 yearly positional | Month-1 (10 -> November) | MonthPosition (4 = last) | MonthItem (8 = Friday) |
| 4 monthly day | MonthDay (15) | 0 | Period (1) |
| 5 monthly positional | MonthPosition (0 = first) | MonthItem (0 here) | Period (1) |
| 6 weekly | DaysOfWeek bitmap (10 = Mon\|Wed) | 0 | Period (1) |
| 7 every N days | Period (u16) (1) | — | — |

`MonthItem` = PjMonthItem, Sunday-first 3..9 (3 Sunday, 4 Monday, 8 Friday, 9
Saturday).  `MonthPosition` = PjMonthPosition 0 first .. 3 fourth, 4 last.
`DaysOfWeek`: bit 0 Sunday .. bit 6 Saturday.  `+80` is **not** a parameter (a
recorded ordinal: 1..7 across the seven records in creation order); `+74`, `+82`,
`+84`, `+86` are 0 in all seven.

Exposed on `core::cal::DatedException`: `period`, `days_of_week`, `month`,
`month_day`, `month_item`, `month_position`, plus `raw_recurrence_words`
(std::array<u16,7>, verbatim).  `core::cal::weekday_of_month_item()` maps
PjMonthItem -> weekday 0..6 / -1.  Decoder: `decode_recurrence_parameters()` in
`core/cal/cal.cpp`, called from `decode_calendar_data()`.

**How the decode is validated:** the `+4` occurrence word is Project's own count
for the range.  All six recurring records agree with the expansion built from
these words (18/7/5/4/5/4 days; the type-1 plain range is 29) — a wrong weekday,
period, month or position changes the count and the expansion refuses.  The
sharpest case: last Friday of November = 2026-11-27, 2027-11-26, 2028-11-24,
**2029-11-30**, excluding 2030-11-29 (past the stored Finish) = 4 = the stored
count.

### 2. Expansion — DONE

`expand_recurring_exception()` is now parameter-driven for types 2..7:

* 2: month+day every year; an absent day (29 February in a common year, a 31st
  in a short month) is **skipped**, never clamped;
* 3: the position-th weekday of the month every year (position 4 = last);
* 4/5: every `period` months, day-of-month / position-th weekday (0 = first);
* 6: every `period`th week, every weekday in the bitmap (week = Sunday-based, so
  the first candidate is the Sunday on or before the start day; days before the
  start are dropped);
* 7: every `period` days from the start day.  Type 7 is how Project stores
  "daily every N days" (period at +76); type 1 is every day and stays a plain
  range.

Only parameters the type does not store (0) fall back to the range's first day
(weekday/day-of-month/month) or to period 1.  **Position is never derived** — 0
is a stored value meaning "first".  Refusals: unchanged four (not recurring,
empty expansion, day cap, occurrence-word disagreement) plus two new parameter
guards (MonthItem that is not a weekday, MonthPosition outside 0..4).

Bounded: every loop is bounded by the 16-bit day range (<= 65535 daily steps,
<= 9363 weeks, <= 2340 months, <= 180 years) and the accumulation stops the
moment the day cap (3660) is exceeded, so no unbounded loop exists even with the
cap disabled.

Plain dated ranges (type 0/1) are untouched: PROJECT_A 1331 and PROJECT_B 1333 exceptions,
all type 1.

  differ from the project-calendar rollup.  No test added.

## Traps added

* The convention change: PjMonthPosition 0 = "first".  A hand-built
  `DatedException` with position 0 expands to the FIRST such weekday; set
  `month_position` for "second" etc.  (W41's derive-from-start-day rule is gone.)
* Type 7 is no longer refused; period 0 there means every day.
* `+80` is an ordinal, not a parameter.  `+74/+82/+84/+86` are zero.
* Type 4's period is read as a **byte** at +78 and type 5's as a **word**,
  mirroring mpxj; do not "simplify" both to u16.
* The weekly mask is Sunday-based bit 0, and the expansion anchors on the Sunday
  of the start week (days before the start are dropped), so a mask without the
  start weekday still starts in the right week.
* `cal_tests` writes no corpus file; the fixture is read-only.  No exception name
  is decoded or printed anywhere (client-data rule).
