## 1. What is done

### 1a. Delete cascade (`core/mppwrite/add_delete.h/.cpp`)

`delete_task_row` no longer refuses when a live link/assignment names the deleted
uid. It now tombstones the dependent rows exactly as Project does
(`docs/analysis/oracle/w11-oracle.md` §2, measured on
`corpus/probe/w11-linkdelete-post.mpp`):

- every `114/TBkndCons` row whose **predecessor (+4) OR successor (+8)** is the
  deleted uid: FixedMeta entry `+0 = 0x02`, `+2 = 0`; `TBkndCons/FixedMeta`
  header `+4 |= 0x02`;
- every `114/TBkndAssn` row whose **task uid (+4)** is the deleted uid: the same
  entry tombstone and `TBkndAssn/FixedMeta` header `+4 |= 0x02`;
- the task row itself, unchanged from W45.

No stream shrinks; no dependent FixedData byte is written. Rows whose entry is
already a tombstone are left alone. After writing, the entry states, `+2` words,
header flags, all non-targeted entry bytes and the dependent FixedData are
re-read from disk and required to match. `DeletedRow` now reports
`link_rows_tombstoned` and `assignment_rows_tombstoned`, plus a warning receipt.

`DeleteOptions::allow_dangling` now covers **only** a damaged file whose
*surviving* live link has an endpoint that already names a dead uid. The default
refuses that (the writer cannot repair it); with the flag it proceeds and names
the orphan rows. Orphan assignments naming an already-dead task uid (PROJECT_B: 10
of 73) are tolerated and warned about, never refused.

Measured byte check (local, no Project needed): `w48-del-cascade.mpp`
(`w11-linkdelete-pre.mpp` + delete uid 2) has `TBkndCons/FixedData` **and**
`TBkndCons/FixedMeta` **byte-identical** to Project's own
`w11-linkdelete-post.mpp`. `TBkndAssn/FixedMeta` differs only at the two
surviving entries' `+2` field-count byte (Project's 2→3 save churn) and
`TBkndAssn/FixedData` only in Project's recalculated cached values.

### 1b. Custom-field values (`core/mppwrite/field_values.h/.cpp`)

`save_field_values(doc, edits, path, table = "114/TBkndTask")` writes Task
custom-field values with the measured encodings (w10-oracle §2):

| kind | store |
|---|---|
| Text | VarMeta block, UTF-16LE + NUL |
| Number | VarMeta block, 8-byte little-endian f64 |
| Date | VarMeta block, 4-byte packed u32 |
| Duration | VarMeta block, u32 **file ticks** (COM minutes × 10; 4800 = 1 day) |
| Flag1 | Task FixedMeta entry byte **+24 bit 0x02** (not VarMeta), mirroring Project's Fixed2Meta `+31/+61 bit 0x80` |

Field ids are the PjTask ids from `analysis/field_id_map.tsv`, reproduced in
`field_values.h` and `core/mpp/field_value.h`. Note the Text family: Text1..6
stride 3 (0x33..0x42), Text7..10 contiguous (0x43..0x46), Text11..30 from 0x13d.

TWO THINGS PROJECT REQUIRES BEYOND THE VALUE, both measured by the failed opens:

1. **VarMeta group placement.** A new entry is INSERTED inside its uid's
   contiguous group, key-ascending (`table.h::insert_var_entry`, also used by
   `add_task_row`), never appended after other uids. Project's own file's uid
   sequence is `[0]*9, [1]*14, [2]*8`, keys ascending, Text1 immediately after
   Name. Our first fixture appended the six entries at the end; Project ignored
   every value.
2. **The field registry in `114/TBkndTask/Props` (mirrored in
   `114/TBkndAssn/Props`).** One 88-byte definition record per field, copied from
   Project's own `w10-fieldvalues.mpp`, sorted by field id (Task) / assignment
   property id 0x09,0x0a,0x28,0x3c,0x3d,0x64 (Assn). The preambles differ:

   | word | Task/Props (86 B preamble) | Assn/Props (88 B preamble) |
   |---|---|---|
   | +0, +4 | u32 size-4 | u32 size-4 |
   | 44+88n | u16 **+30** | u32 **+32** |
   | count | u32 **+78** | u32 **+80** |
   | count*88 | u32 **+82** | u32 **+84** |

   Everything else in the preamble is unchanged. Both of our emitted registries
   are now **byte-identical** to Project's own streams (Task 614 B, Assn 616 B),
   asserted by the field test. Only six fields have measured records (Text1,
   Flag1, Number1, Number2, Duration1, Date1); any other field is refused.

3. **FixedMeta tail presence bits + the Duration marker.** Even with perfect
   VarMeta/Props, Project needs a third store in the 47-byte FixedMeta entry:

   | field | tail |
   |---|---|
   | Text1 | `+21 |= 0x20` |
   | Flag1 | `+24 |= 0x02` (the bool; False clears it) |
   | Number1 | `+25 |= 0x08` |
   | Number2 | `+25 |= 0x10` |
   | Duration1 | `+26 |= 0x01`, `+27 |= 0x20`, plus VarMeta key 0x0b4000b7 = `07 00` |
   | Date1 | `+29 |= 0x40` |

   The six-field tail is `+21=0x20, +24=0x02, +25=0x18, +26=0x01, +27=0x20,
   +29=0x40`; the entry's `+2` u16 is the row's exact VarMeta entry count
   INCLUDING the marker (base 11 -> 17). The marker is inserted in normal
   ascending-key order (after the overtime entries, before Date1).

Writing a **new** field appends a block to Var2Data, inserts a 12-byte VarMeta
entry in its uid group, and increments the row's FixedMeta `+2` field count and
VarMeta's declared count. **Overwriting** appends a block and repoints the
existing entry; counts stay put and the old block is left orphaned (the same
append-only scheme `table.h` uses). Registration happens once per table; a
rewrite adds nothing, and clearing a flag leaves the registration in place. Every
write is validated first, applied to a copy, saved, re-opened and re-read; only
the intended streams may move (FixedData and Fixed2Data byte-identical, `214/`
untouched, VarMeta proved by entry multiset + uid-group ordering, Props by record).

Refused with a reason (never guessed): **Cost1..Cost10** (storage unmeasured —
no oracle fixture stores a cost), **Flag2..Flag20** (only Flag1's bit position is
measured), any field without one of the six measured Props records, any id
outside the six families, a `kind` that does not match the id, uid 0, a
missing/tombstoned row, duplicate edits, an invalid date, a non-finite number,
text with an embedded NUL, and a missing output directory.

**Inference still open:** whether the Fixed2Meta Flag1 mirror is *required* on a
fresh open (it is Project's measured write shape and Flag1 passed with it), and
whether registration in Props is sufficient without the Assignment VarMeta side.
If the third open still shows zeros, the next probe is `114/TBkndAssn/VarMeta`.

### 1d. Linked-pin contract (`core/mppwrite/save.h/.cpp`)

`save.h`'s "HONEST LIMIT (unmeasured)" paragraph is replaced with the measured
result (`w11-oracle.md` §1): SNET is "start no earlier than", so a linked
successor reopens at `max(predecessor finish, pin)` while ConstraintType/Date read
back exactly (4 / 2026-10-21 08:00). A writer must not claim an exact start on a
linked row; the app should warn.

New pure predicate, no scheduling change:

```cpp
bool mppwrite::pin_would_be_clamped(std::uint32_t pinned_start,
                                    std::uint32_t earliest_dependency_start);
```

True when the pin predates the dependency-allowed start; false if either packed
date is invalid (0 / 0xffffffff) — "not enough information", never "the pin will
stick".

## 5. Verified vs inferred

  the assignment rows with it as task uid; sets entry `+0=0x02`, `+2=0` and the
  table header `+4` bit; leaves dependent FixedData and every other stream
