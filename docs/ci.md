# CI

`.github/workflows/ci.yml` is the portability oracle: the project targets macOS
but is developed on Windows, so a green `macos-latest` run is the only evidence
that the core is portable. This file records what the workflow actually does, why
it does it that way, and how to reproduce it on a local machine.

## The job

One job, `build-and-test`, with `fail-fast: false` and `timeout-minutes: 30`:

| matrix entry | runner | generator |
|---|---|---|
| `windows-msvc` | `windows-latest` | Ninja, after `ilammy/msvc-dev-cmd@v1` |
| `macos-appleclang` | `macos-latest` (arm64) | Unix Makefiles |
| `ubuntu-gcc` | `ubuntu-latest` | Unix Makefiles |

Windows uses Ninja because `windows-latest` stopped exposing an installation the
"Visual Studio 17 2022" generator could find; `msvc-dev-cmd` provides the same
`cl.exe`/`INCLUDE`/`LIB` environment as `vcvars64.bat`, so the compiler and flags
are identical to a local build. Locally the Visual Studio generator is still the
right choice — see the Ninja trap in `docs/build.md`.

Steps, `shell: bash` on every platform so the commands are the same everywhere:

```sh
cmake -S . -B build -G "<generator>" -DCMAKE_BUILD_TYPE=Release -DCORE_WARNINGS_AS_ERRORS=ON
cmake --build build --config Release          # no --parallel anywhere
ctest --test-dir build -C Release --output-on-failure --timeout 60
MPP_NO_CORPUS=1 ctest --test-dir build -C Release --output-on-failure --timeout 60 -R '^mpp_reader$'
```

The last step is a second, focused run of the reader test with the corpus forced
absent; it is cheap and it is what stops the committed-fixture path from rotting.

Warnings are errors on all three (`-DCORE_WARNINGS_AS_ERRORS=ON`), so a warning
on one compiler is a red build rather than a line nobody reads. `--timeout 60`
turns a wedged test into a failure instead of a hung runner.

## What runs on a clean checkout

`corpus/` is git-ignored (it holds a client's construction programme), so a
runner has no real `.mpp` files. Every test is registered and runs; the reader's
checks that need the corpus skip, with a `SKIP:` line in the log, rather than
fail:

| test | needs `corpus/`? | on a runner |
|---|---|---|
| `core_field_table`, `core_field_table_generator_check` | no | runs |
| `mpp_reader` | no — `tests/data/synthetic-base.mpp` is committed | runs |
| `core_sched_*`, `mppwrite_*`, `view_model`, `io_*` | per stream | runs |
| the PROJECT_A/PROJECT_B golden comparisons, the `corpus/probe` sweep | **yes** | print `SKIP:`, pass |

The reader test list grows as streams land; `ctest -N` on the machine being built
is the source of truth, not this table.

## The reader fixture, and why the exclusion is gone

Until 2026-10-22 CI carried `ctest … -E '^mpp_reader$'` with a dated `TODO`. Two
reasons: W6's harness aborted on Windows with a modal CRT dialog (a hang, not a
failure, on a runner), and there was no `.mpp` on a runner for the test to read.
Both are fixed:

- the harness redirects CRT error reporting to stderr (`_set_error_mode`) and
  catches every exception, so a crash is a failure with a message;
- `tests/data/synthetic-base.mpp` is committed: 237,568 bytes, 3 tasks plus the
  project row, generated by the coordinator through MS Project's COM automation.
  It is synthetic, **not client data**. Provenance, hash and the "do not replace
  it with a client file" rule are in `tests/data/README.md`.

The test finds the fixture without depending on the working directory:
`core/mpp/CMakeLists.txt` already configures the committed golden TSV's absolute
path (`MPP_GOLDEN_PATH`), and the fixture sits beside it, so the test uses that
directory. `tests/test_paths.h.in` additionally exposes `TEST_DATA_DIR` for any
target that wires the configured header in; when defined, it takes precedence.

`MPP_NO_CORPUS` (any non-empty value) makes the PROJECT_A, PROJECT_B and `corpus/probe`
checks take their absent path on a machine that does have the corpus. That is how
the fallback is proved locally without renaming or touching the client files:

```bat
ctest --test-dir build\vs -C Release --output-on-failure --timeout 60
set MPP_NO_CORPUS=1
ctest --test-dir build\vs -C Release -R "^mpp_reader$" -V
set MPP_NO_CORPUS=
```

Expected in the second run: `SYNTHETIC: 3 tasks`, then three `SKIP:` lines (PROJECT_A,
PROJECT_B, probe sweep), then `PASS: 52 checks`.

## Reading a failure

- Configure failure mentioning "could not find any instance of Visual Studio":
  the Windows job lost its MSVC environment step — restore `msvc-dev-cmd`, do not
  drop Windows from the matrix.
- `mpp_reader` fails with "committed fixture … is missing although …
  project_a_golden.tsv is present": the fixture was not checked out or not committed.
  It is a deliberate **failure**, not a skip — a tree with `tests/data/` must
  contain both files. Check `tests/data/synthetic-base.mpp` is in the checkout.
- Any test that prints `SKIP:` and passes on one platform but not another: read
  the message — the corpus-only checks are expected to skip everywhere.

  needs a coordinator commit and push; agents cannot push). Verified locally on
  Windows/MSVC only: build clean at `/W4 /WX`; `mpp_reader` passed with the corpus
  (`PASS: 106 checks`) and with it forced absent (`PASS: 52 checks`); the suite
  was 12/12 at the time, with further tests landing from other streams while this
  was written.
- `windows-latest` under Ninja + `msvc-dev-cmd` had not run at all before this
  change; its first run is still the open portability question in
  `docs/build.md`.
- `macos-latest` is arm64. An Intel Mac is a second, untested architecture.
